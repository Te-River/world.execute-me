# world.execute-me

一个纯 HTML 的仓库，用来表现 Mili —《world.execute (me) ;》这首乐曲的 MV。
画面不是随机生成的可视化，而是**由对这个 MP3 文件本身实测出来的数据驱动**的。

## 怎么跑

```
双击 index.html 即可            # 全部本地资源，不需要构建、不联网、不装任何依赖
```

## 实测出来的结果

下面每一个数字都来自 `analysis/analyze.html`：它用浏览器自带的 MP3 解码器拿到 PCM，
再跑一条纯 JS 的 DSP 链（无任何第三方库、无 ffmpeg）。

| 项目 | 实测值 |
| --- | --- |
| 时长 | 211.907 秒（3:31.91） |
| 封装 | MPEG-1 Layer III，320 kbps，44.1 kHz 立体声，编码器 `Lavf58.76.100` |
| 标签 | Mili — *world.execute (me) ;*，专辑 *Miracle Milk*，第 11 轨 |
| 分析域 | 48 kHz 浮点 PCM（浏览器重采样），9 932 帧 @ 21.33 ms |
| 频谱 | 8 个对数频带（25 Hz – 16 kHz），Hann 窗，4096 点 FFT，75% 重叠 |
| 响度 | 峰值 1.0397，RMS 0.3361，3 062 个削波采样点（母带压得很满） |
| 静音 | 起始 0.107 秒，结尾余音 0.021 秒 |
| 调性 | A 小调（Krumhansl–Schmuckler r = 0.479），其后 F 大调 0.323、G 大调 0.275 |
| 速度 | 128.3 BPM，置信度 0.15，竞争解 88.5 / 66 |
| 结构 | 14 个新颖度边界 → 0/15/31/44/60/74/88/104/119/134/147/163/175/193 秒 |
| 旋律 | FFT 自相关求 f0，65–1 200 Hz，带相关性门限 |
| 立体声 | 侧/中能量比（画面横向扩散跟着它走） |

**速度这个值我没有直接采信。** 检测到的乐句边界相对该小节网格平均偏差 556 ms，
而随机偏移的期望值是 468 ms（bar/4）——也就是说结构并不支持这个节拍。
但歌词提供了独立的旁证：2:27.66 起的 12 次 `EXECUTION` 诵唱间隔 0.94 秒
= 每词两拍 → 127.5 BPM，与实测 128.3 BPM 吻合。
所以画面里的脉冲不跟节拍器，而是跟从 flux 包络上实测出的 onset（全曲约 500 个），
它们与录音天然同相。

## 画面在做什么

它是一支 MV，不是频谱读数。全片发生在一间暗房里，**唯一的光源就是那张纸**：歌词说到什么，
什么就被墨线画在这张发光的纸上，房间保持全黑。所以没有"背景"可设计——只有灯、光照到的地方、
以及逆着光的剪影。

逐句对齐：通电与合闸、纸上写下的字段（`me.heart = null` 用绯红，正是那句 used before defined）、
被创建的**对象**立方体、摆开的棋子、罩住一切的 PROTECTION 穹顶、封在球里的小世界与球里的片名、
散点长出坐标轴、圆与展开的周长、可以坐上去的切线、趋近无穷的渐近线、交流整形成直流、
合上的眼睑、旋涡、被倒着擦过的时间轴、两个圆交叠、光标走向心、`> run execution` 与落下的铁栏、
一张跑起来的类型表（`switch (me.form)`：茄子/番茄/狸猫各是一个 case 的返回值，一次只点亮一个）、
内存里只剩一个实例与落在它与虚线插座之间的 PROOF 印章、♀♂ 换位、从早到晚的钟面、
S 与 M 对调、出神的同心圆、进度条走到 COMPLETION、被一条条切断的**星型拓扑**（六句"你走了"）、
删去的碎片、**被挖掉一颗心的心**（DISHEARTENED／无心）、`IllegalArgumentError` 的堆栈跟踪、
然后——房间变成判决的颜色。

`EXECUTION` 段是这张纸变成**处决令**的时刻：绯红墨、逐行点验、每判一行盖一枚朱批；
`If I can have you back` 从最后一行往上把它们逐行划掉，旁边那个插座已经空了。
之后是爱的代数式、铁栏收成心的轮廓、灯缩成一扇窗、最后一道红线、以及待机灯的一下呼吸。

逐句对齐是**审计**出来的，不是感觉：SATISFACTION 的心原先在 61.95 秒就出现了（比歌词早 3.4 秒）、
DISHEARTENED 处错放了 ILLEGAL ARGUMENTS 对话框（早 6.3 秒）。现在心落在 65.39、"无心"落在 124.89、
堆栈跟踪落在 131.22。

`EXECUTION` 段不再是红色长条图，而是**程序清单本身**：它被画成一张不透明的纸——
一份用绯红墨水写在淡色纸上的**处决令**，压在黑红底上。每诵唱一次，红字标记往下走一行，
最后落在 `throw` / `process.kill(me)` / `exit(0)` / `return you;`，每判一行盖一枚朱批。
`If I can have you back` 则从最后一行往上把它们逐行划掉。
纸牌是不透明的，这是"元素不再压住代码"的结构性保证：铁栏、剪影、字幕带都只能落在纸外。
清单只放 runtime 那 10 行——class 本体在 OBJECT CREATION 时就已经写在世界上了。

## 歌词重读：说话的就不是一个人

你提醒"主题其实没有必要是个人"之后，我把歌词逐句重读了一遍。这一读改掉的不止是道具，
因为**说话者从头到尾就不是人**——它是被创建、被填参数、被世界执行的一个实例：

| 段落 | 唱的是什么 | 读出来的是什么 |
| --- | --- | --- |
| 0–16 | Lay down your pieces / OBJECT CREATION / Fill in my data parameters | 落子的是你，被填的是我。出生之前字段就写好了，其中 `Heart heart;` 从未初始化 |
| 29.7–44 | 散点 / 圆 / 正弦 / 趋近无穷 | 四句是同一个条件句：换成任何一种数学形状，交出去的都是"定义我的那个量"。最后一句最狠——我的边界由你来给 |
| 44–59 | switch my current / gender / role，AC→DC，AM→PM，F→M，S→M | 电流、性别、位置、时间全是可赋值字段。这不是一个人换装扮，是一个对象改配置 |
| 59–74 | give you all the STIMULATIONS → be your only SATISFACTION | 一笔交易：我做你唯一的刺激源。亲密在这里已经被"可测量的量"换掉了 |
| 74–88 | 茄子 / 番茄 / 狸猫 / 唯一的神 | 排比继续，词库从数学掉到菜市场：能给的全给了。然后跳到"若我是唯一的神，你便是我存在的证据"——唯我论需要一个见证者 |
| 110.9–118 | you have left × 6 → ISOLATION | 全片的转折，而且是**拓扑**的转折：网络里六条连线按六句词一条条断，孤岛是字面意义的孤立节点 |
| 118–131 | erase the pointless FRAGMENTS / DISHEARTENED / ILLEGAL ARGUMENTS | 碎片是待回收的对象；DISHEARTENED 是 heart 这个组件被删（回指开场那句从未初始化）；"非法参数"是运行时异常，不是吵架 |
| 147–162 | EXECUTION × 12，然后 EIN/DOS/TROIS/NE/FEM/LIU | 动词从"执行"滑向"处决"。六种语言数到六，是一场多语种的宣判 |
| 162–170 | give **them** all the EXECUTION → be your only EXECUTION | 全曲最暗的一句：如果我把所有人都处决掉，就能做你唯一的刽子手。所以这里是一排节点依次被划叉，最后只剩 `me → you` 那一条线 |
| 184–191 | I know the algebraic expression of LOVE / though you are free, I am trapped | 答案就是第一段那张图：极限永远逼近、永远碰不到那条线。它把爱完全学会了，仍然被囚——知识不救命 |

于是这一轮把还剩下"人"的地方全换掉了：

- 主体从剪影的人改成一个**节点**（`G.subject`）。它的表情只有一种：是否还受光。`kneel` 是沉向地面，
  `empty` 只剩一个虚线插座，`dead` 是被划叉。
- "你还是走了"原来是窗边一个人影，现在是**星型拓扑**：一个 hub，六条臂随六句歌词逐条断开并盖红叉；
  到 ISOLATION 时 hub 仍然亮着，但已经没有可发的地方。
- "如果我是一根茄子"原来是三张标本并排（静物画），现在是一张跑动的**类型表** `switch (me.form)`：
  一次只点亮一个 case，图版是那个 case 的返回值。
- "如果我是唯一的神"原来是头顶光环，现在是内存里只剩一个实例，它与另一个虚线插座之间落一枚 PROOF——
  存在是被**指认**出来的。
- "give them all the execution" 原来是铁栏加一把刀，现在是队列里七个节点依次划叉，最后 `me → you`
  的线加粗，刀挂在这条线上。
- 宣判倒计时原来是一个人跪在大数字前，现在是六个节点，每说出一种语言就熄灭一个。
- 结尾 `love(x) = lim x→∞` 不画新图形，而是把第一段那条渐近线**原样画回来**（同一个 `G.approach`），
  并在虚线旁写回那句 `// you can be my limitations`。开场与结尾于是是同一张图的两次阅读。
- 片尾被划掉的最后一行由 `return her;` 改成 `return you;`——它要归还的从来不是"她"，是"你"。

## 关于中文与典故

英文是原唱，中文是我重写的，不参照原 LRC 的翻译——因为几个双关只有选对中文词才立得住：
`OBJECT CREATION` → 创建**对象**（既是实例，也是恋人）；`EXECUTION` 在前半保持"执行"、
到诵唱后半才变"处决"（执行代码与执行死刑共用这个动词）；`To AC to DC` → 由**交流**换成直流；
`DISHEARTENED` → **无心**（无情，也是 heart 这个组件被删除）；`LIMITATIONS` → 极限。

典故也换到了这首歌真正所属的脉络里（我最初误用了中文典故）：
被写上一个词才活动的**戈仑**（对应 OBJECT CREATION / INITIALIZATION，最后的 EXECUTION 就是那一笔擦除）、
**柏拉图的洞穴**（对应 trapped in this strange strange SIMULATION）、
**巴别塔**（EIN/DOS/TROIS/NE/FEM/LIU 六种语言）、**俄耳甫斯回头**（If I can have you back）。
庄周梦蝶没有进字幕——机器会把它写在日志里，所以它出现在运行控制台：
`butterfly_check: who is dreaming whom`。

### 先正确识别音乐

新增 `analysis/music.html`（浏览器内、零依赖，和 analyze.html 一样自己解码 MP3）跑出的**音乐层**，
导出为 `mv/music.data.js`：

| 实测 | 值 |
| --- | --- |
| 速度 | 128.00 BPM（onset 自相关 + 谐波增强，128 附近给对数正态先验） |
| 节拍 | 451 拍，逐拍力度（该拍实测 onset 权重 0–255） |
| 拍号 | 4/4，113 小节，重拍相位 = 1（按四拍分组里 onset 最强的一组定"一"） |
| 旋律 | 22 050 Hz 单声道、2048 点自相关求 f0，55–1100 Hz；主歌 91–92% 的帧有音高，副歌 70%，诵唱段 87% |
| 旁证 | 诵唱段 12 个 EXECUTION 间隔 0.94 s = 两拍 → 127.7 BPM，与实测 128.00 吻合 |

**和弦解码没有进片子。** 逐小节模板匹配把一首 A 小调的歌读成了以 B♭ 为主（40 小节 A#、25 小节 F），
这个结果没有通过自检——宁可不用，也不让画面去依赖一个我不信的数。

### 再让画面对它负责

1. **摄影机交给节拍**：每小节内缓推、到下一小节头释放（呼吸周期就是小节，不再是各幕自定的慢变焦）；
   强拍的额外推量取自**那一拍实测的 onset 权重**，所以鼓重的段落画面自然更用力。
2. **切点吸附到小节线**：离小节线 1/4 拍以内的镜头切换一律挪到小节线上（卡点）。
3. **一条旋律线贯穿全片**（`mv/line.js`）：横向是时间，纵向是对数音高，走的就是实测 f0；
   笔头发光，下方一条虚线倒影。**它画在纸的后面**，被纸挡住的部分由纸的光吃掉——
   所以这条线是"从灯后面走过去"的，和这间屋子的物理一致。每个音符的起点与终点有 0.12 秒淡入淡出，
   否则一次断音就是一帧闪屏（校验台在 50.16 秒抓到过）。
   线还会**变形**：SIMULATION 时它闭合成一圈，诵唱段它折成一排栅栏，
   最后拖长的 LO-O-OVE 里它**压平成一条永远走不到的水平线**——和纸上那条渐近线互为对位。
   这里返过两次工：一开始我让线去画圆、正弦、心形、星型，逐帧图一看**全废**——
   纸面上同一时刻正画着带标注的圆/正弦/心/星，一帧里出现两个同样的形状，
   正是我上一轮承诺消灭的"东西太多"。换成 PROTECTION 的罩子后**又废了一次**：
   那一镜的纸上本来就画着一只穹顶。所以判据是"纸画不了的"，最后留下三样：
   一圈闭环、判决的栅栏、以及那条渐近线本身。**纸负责论证，线负责演唱。**
4. **被唱到的大字进入画面**：歌词里那些全大写的钩子词（DIMENSION、CIRCUMFERENCE、SATISFACTION、
   ISOLATION…共 44 处）以 Georgia 显示字重出现在房间的暗部，按该音符占有的时值从左往右擦出，
   带 ±5 px 的印刷套色错位，中文重译退到它下面一行；同样在纸后面，于是字是**从光里长出来的**。
   字号随摄影机缩放反向调整（`fit = 1.06/z`），否则紧取景会把整句话吃进纸里。
5. **强拍的推法有包络**：起拍那一瞬不是瞬间到位，而是 60 ms 起音、220 ms 释放。
   之前它是阶跃的，全扫里最后一个未归因尖峰（50.158 秒）就是它。

### 联系表才看得见的四个毛病

定点图一张张都过得去，把 0–105 秒按每秒一格拼成一张联系表来看，才看见四个全片层面的问题：

| 毛病 | 在联系表上的样子 | 改法 |
| --- | --- | --- |
| 16–29 秒是死场 | 连续 14 格几乎同一幅画：一个灰盘子里一个点 | 那颗球本来是"被递过来的小世界"，但它是**灰的**——这间屋子的前提是只有纸会发光，一颗不亮的球读起来像灯被关了。把球面提亮（与房间色只混 16%），并把片名 `world.execute (me) ;` 作为大字在 16 秒起擦出（大字窗口对片名行放宽到 5.4 秒） |
| 六套色板看不出来 | 主歌与副歌在缩略尺度上是同一种白 | 病根在 `page()`：纸面渐变顶部**向白色混了 35%**，把整块色板洗掉了。降到 16%，底部向灯色混到 34%；同时把三块主要色板推深（主歌普鲁士蓝 page `#cfe1f4`、副歌黑朱红金 page `#f9e3bd`、揭示段淡紫 page `#e3e4f8`） |
| 旋律线在琶音段读成栅栏 | 0–16 秒两侧一片竖直方波 | 纵向跨度从 0.30 屏高压到 0.215， contour 还在，但不再像围栏 |
| 副歌 59–66 秒太薄 | 一张发白的纸上只有一个很小的心 | 涟漪本来挂在 61.95（STIMULATIONS 那个词），提前到 59.68（"If I can give you all the" 一开口就开始），副歌入口不再空转 |

改完全片重扫：细节密度 40.8 → **38.0**，运动均值 0.84 → **0.70**——四个毛病里有两个本来就是"太挤/太闹"。

翻到第二张联系表（106–211 秒）又抓到同一类毛病的两处，一起修了：

- **193–205 秒是 12 格灰色方块。** 结尾"灯离开房间"用的板色是中性灰 `#7d8790`，缩略尺度上和"没点亮的道具"
  完全同形——和那颗灰球是同一个错误。改成余烬（page `#8d7a63`、glow `#6b4a34`），并把窗内那层光的衰减
  从线性改成 `pow(1-k, 0.55)`：它先亮着，再一下暗下去，而不是匀速褪成灰。
- **136–147 秒堆栈跟踪被拿走之后，跪着的那个节点在画面里消失了。** 那一刻房间里确实没有灯，
  但"没有灯"和"没有人"是两件事：给它脚下加一小滩自己反射的光池（挂在实测低频能量上），
  `heap quiet. nothing scheduled.` 才仍然是**一个幸存者在空房间裡**，而不是一张黑屏。

最终一轮全扫（同一构建，25,429 帧）：0 黑帧、0 爆白、0 抛异常、**0 未归因闪现**；
细节密度 38.0、运动均值 0.70、全片最低亮度 10。

### 这一轮之后的逐帧结果

同一构建重扫 25,429 帧（120 fps）：**0 黑帧、0 爆白、0 抛异常**；25 个孤立尖峰里 12 个是溶解窗口、
13 个在声明了 `cut: true` 的诵唱段，**未归因的闪现：0 个**。全片最低亮度 12（片尾熄灯），
各幕平均运动 0.5–1.1（全片均值 0.70）、峰值最高仍在诵唱段（52）。

代价要算清楚：细节密度（画面平均梯度）从上一轮的 33.1 涨到 **38.0**，帧间运动平均从 0.2 涨到 0.70。
这是故意的——多出来的两层不是道具，是录音本身（一条旋律线、一个正在被唱的词）。
它们和"14 栋房子加 5 根电线杆"的区别在于：前者只有两个元素且都跟着音乐动，后者是十几个互不相干的
静态细节。如果你觉得又挤了，要砍的应该是这两层里的一层，而不是回到彩纸和山脊。

跑法多了一步：`VERIFY.smoke()` 先踩八帧（每种时刻一帧）看有没有抛异常，再跑 250 秒全扫。
这一轮就是靠它当场逮到摄影机里一个 `clamp` 未定义——那会让**每一帧**都抛，全扫要两分半才发现。

## 三次返工：从可视化到一间暗房

**第一轮**是亮色纸面配灰线，被指"颜色呢"——量出来确实是问题（亮段饱和度实测 0.01–0.04）。
**第二轮**改成饱和地面色 + 两档山脊 + 大太阳 + 平涂道具，颜色够了，但被指"太乱"，
再被直接判为"非常丑"。回头看，病根不在配色而在**语言**：canvas 擅长画光、衰减、剪影，
不擅长画卡通小物件；我让它去画茄子、狸猫、棋子、房子，它就一律给你 clip-art。

**第三轮（现在这版）换了语言**：房间全黑，**那张纸是唯一光源**。歌词说到什么，就用墨线画在
发光的纸上；情绪不再靠换色相，而靠灯——副歌过曝、崩塌段灯丝烧黄、诵唱段房间变成判决的颜色、
结尾是灯离开房间。先做了三张真渲染的风格样片（`style-a/b/c.jpg`）选定方向，才动手重写。

这条语言顺带解决了两件事：所有图元都被**裁在纸内**，物理上不可能再压到字幕或彼此叠穿；
以及"一帧里有多少东西"从十几个常驻图层降到"一间屋子、一张纸、一个节点"。

转场的病根与配色无关，而在**每个镜头各自持有摄影机**：溶解时新旧两幅画用不同缩放，
于是变成"带淡入的跳切"。现在全片只有一条摄影机轨道，切点处保持上一镜落幅、用 0.8 秒滑入
下一镜起幅；溶解时长随响度从 1.15 秒收紧到 0.45 秒。镜头内部换取景原本是**单帧瞬移**
（16 处，逐帧扫出来的），现在除诵唱段外一律 slew 过去；诵唱段的硬切是它的剪辑语法，保留。

刻意**没有**做的：跟随鼓点的闪光、切片故障、以及摄影机无目的的漂移。之前有一条按响度缩放的
二阶正弦漂移常驻每一帧（幅度 8–26 像素），读起来像"画面静不下来"，整个删了。唯一保留的震动
在高潮段，由镜头自己声明 `shake` 才生效，幅度挂在实测 onset 的冲量上——鼓点停，画面就停。

设计空间原来用 `cover` 铺满窗口：窗口一旦不是 16:9，画面两侧就被裁掉，代码清单会少掉左边几列。
现在改成 `contain` 加黑边，1600×900 这一页在任何窗口比例下都完整可见。

一个需要你知道的取舍，以及它的修正：第三版曾**刻意接近单色**（房间黑、纸白，全片只有那一抹绯红），
当时我认为要更花就得走回第二轮那条会被判丑的路。看了 Luminite 之后发现这条路是存在的：
**每个段落只用有限的几块颜色，但段落之间换整套**。现在全片是六套三色板——
开场中性纸白、主歌普鲁士蓝的夜、副歌黑/朱红/金、崩塌段褐黄、`EXECUTION` 判决红、揭示段淡紫冷光，
结尾是灯离开房间。房间始终是全黑的，颜色活在那盏灯的温度里。

所以"乐器是不是两种"这个直觉是对的，而且能在 PCM 里量出来——我把它做成了
`VERIFY.timbre()`，每 15 秒一格：

```
        0s  15s  30s  45s  60s  75s  90s 105s 120s 135s 150s 165s 180s 195s 210s
平坦度   23   53   22   24   54   18   25   43   41   18   21   55   51   73  240
有音高   94%  51%  73%  73%  29%  67%  72%  44%  53%  62%  62%  28%  37%  83%   0%
```

主歌段平坦度 18–25、有音高比例 60–94%（旋律与合声在说话）；一到副歌入口、诵唱段、
结尾的芯片琶音，平坦度跳到 43–73、有音高比例掉到 28–37%（噪声性、打击性的材料浮上来）；
最后 10 秒是纯噪声尾音（平坦度 240，几乎没有音高）。
**亮度反而不是区分两者的量**（高频能量占比全程稳定在 19–25%），区分它们的是"有调 / 无调"。
胶片颗粒的强弱因此挂在实测平坦度上，而不是挂在响度上——听到的是噪声层浮上来，
看到的才是画面变粗。

需要说清楚的是：DSP 只能把材料分成"有调 / 噪声性"，**不能凭频谱报出乐器名字**。
上面关于编制的说法来自乐队自己的公开资料，不是我从音频里"听"出来的。

## 校验：逐帧扫，不是抽查

按"每秒校验 60 次画面、后来调到 120 次"的要求，`analysis/verify.js` 把全片 211.907 秒按
120 fps 展开成 **25,429 帧**（`VERIFY.start(120)`），每一帧都真的渲染出来再量：

- `MV.pin(t) / MV.step(ts)` —— 播放器暴露的可 pin 时钟。靠 `track.currentTime` 是做不到
  逐帧的：媒体 seek 要一个异步往返才能改变播放位置，而 seek 的粒度也远大于 16.7 ms。
- 每帧量四个数：亮度均值、饱和度均值、**与前一帧的差**（运动量）、以及摄影机本帧的位移速率。
  运动量是症状层的量——"画面在乱抖"这件事只能在这里被证伪；摄影机速率是原因层的量。
- 每 60 帧取一格，同时拼出每秒一格的接触表（`sheet-a.jpg` / `sheet-b.jpg`）。
- 阈值：亮度 <8 记为黑帧，>247 记为爆白，帧间运动 >70 或摄影机速率 >26 记为跳帧。

一个注意点：分析数据本身是 21.33 ms 一帧（46.9 fps），所以 60 fps 下部分帧只是插值差异。
仍然要按 120 fps 扫——因为画面是按帧显示的，一帧的闪屏在 47 fps 采样下会被整个漏掉。
事实正是如此：**这条链路上抓到的三个 bug，有两个只存在于个别帧上，第三个只在时钟被倒着拨时出现**。

| 抓到的 | 症状 | 根因 |
| --- | --- | --- |
| 片尾 3 帧全黑并抛异常 | `addColorStop('#NaNNaNNaN')`，t ≥ 211.886 | `NF` 取了 base64 **字符串**的长度 13,244，而解码后只有 9,933 帧；末尾越界读到 `undefined` → NaN 一路传到渐变色 |
| 16 处单帧跳变 | 运动量曲线上 4.8 / 47.7 / 49.5 / 51.4 / 55.1 / 77.6 / 81.4 / 85.1 / 92.0 / 95.5 / 99.3 / 103.5 / 117.3 / 124.9 / 179.9 / 180.9 秒各一根针 | 镜头内部换取景是瞬移（第 N 帧宽、N+1 帧紧，中间没有过渡）；现在除诵唱段以外一律 slew 过去 |
| 时钟倒退一次，整片从此不刷新 | 逐帧扫时 23,616 / 25,429 帧被标记，异常是 `rgba(0,0,0,Infinity)` | `render()` 拿 `(ts-lastTs)/1000` 当 dt，倒带时 dt 为负，`1-exp(-dt/τ)` 溢出成 `-Infinity`，把调色板污染成 `±Infinity` 且**永久粘住**（渐晕那一行最先抛）。真实用户点一下波形上更早的位置就会踩到 | dt 先 `Math.max(0, …)` 再进任何平滑器 |

摄影机必须走到每一张前面；改成类型表之后一次只看一个 case，摄影机换成一整段缓推，这 163 帧随之消失。

也就是说：全片运动量最高的一幕仍然是诵唱段（平均 0.6、峰值 53），其余各幕平均 ≤0.3，
崩塌段几乎是 0（那是"heap quiet. nothing scheduled."，画面本来就该停住）。
剩下的尖峰不再是单帧的针，而是**衰减的斜坡**——正是一条 0.5 秒的运镜，不是跳帧。

另外还顺手修了一个不报错的 bug：彩纸的 `g.rotate(t*(0.6+f.d)+f.ph)` 里 `f.ph` 从来没被赋值，
`rotate(NaN)` 让 CTM 不可逆，于是**彩纸一直没画出来**——它只在画面上表现为"少了点东西"，
代码层面完全看不出来。

那是诵唱段**要求**的硬切（`scene.cut`），不是残留的抖动。

### 120 fps 才看得见的那类 bug：闪现

你说"调到 120 张每秒，然后你就会发现部分元素在闪现"。确实如此，而且 60 fps 扫不出来：
一次闪现只有一帧，在 120 fps 下它是一根 8.3 ms 的针。

判据不能只是"这一帧和上一帧差得多"——硬切也差得多。所以每个孤立尖峰要**先归因再计数**：

| 归因 | 规则 | 算不算 bug |
| --- | --- | --- |
| `dissolve` | 落在某个切点 ±1.5 秒内（溶解最长 1.15 秒） | 否，转场本来就要换画面 |
| `hard-cut` | 落在声明了 `cut: true` 的镜头里（诵唱段的剪辑语法） | 否，那是设计 |
| `FLASH` | 其余：元素在镜头内部凭空出现、消失或被重新驱动 | **是** |

归因之后计数为 0（下表是修完之后的最终一轮）。修掉的三处真闪现：

| 时间 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 69.15 s | `> run execution` 每 0.09 秒"跳"出一个字符 | 打字机写成 `slice(0, floor(u*20))`，一个字形在一帧内从无到有 | 改成一条连续变宽的裁剪带，字是被擦出来的 |
| 134.8 s | 堆栈跟踪那一页整页消失 | `if (t < 134.8)` 是硬门，一帧之内整张纸没了 | 让纸连同裁剪一起在 134.8–135.55 秒淡出 |
| 各切点 | 溶解窗口随响度实时改变 | 混合期间音乐变响 → 窗口缩短 → 条件中途转假 →  incoming 画面被弹回去 | 溶解时长改为在**切点那一刻**取样（`dissolveLen(nxt.from)`），窗口一开就固定 |

还有一处不算闪现、但同样只有逐帧才看得见：`void` 里的光标用 `Math.floor(t*2)%2` 开关，
每 0.5 秒硬开硬关一次；改成余弦呼吸之后它不再产生边界帧。

顺带说一个只在真渲染下才会暴露的排版 bug：逐字打字需要按字宽排 x，而 `measureText` 用的是
**当时**的字体——上一次 `G.text` 把字号改成了行号的小字号，于是整行字符叠在一起。
1920×1080 的定点图一眼就看出来了（`> run exe.cuti..`）。这也是这一轮改成裁剪带的原因之一。
