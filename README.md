# world.execute-me

一个纯 HTML 的仓库，用来表现 Mili —《world.execute (me) ;》这首乐曲的 MV。
画面不是随机生成的可视化，而是**由对这个 MP3 文件本身实测出来的数据驱动**的。

## 怎么跑

```
双击 index.html 即可            # 全部本地资源，不需要构建、不联网、不装任何依赖
```

## 实测出来的结果

下面每一个数字都来自 `analysis/analyze.html`：它用浏览器自带的 MP3 解码器拿到 PCM，
再跑一条纯 JS 的 DSP 链（无任何第三方库、无 ffmpeg）。

| 项目 | 实测值 |
| --- | --- |
| 时长 | 211.907 秒（3:31.91） |
| 封装 | MPEG-1 Layer III，320 kbps，44.1 kHz 立体声，编码器 `Lavf58.76.100` |
| 标签 | Mili — *world.execute (me) ;*，专辑 *Miracle Milk*，第 11 轨 |
| 分析域 | 48 kHz 浮点 PCM（浏览器重采样），9 932 帧 @ 21.33 ms |
| 频谱 | 8 个对数频带（25 Hz – 16 kHz），Hann 窗，4096 点 FFT，75% 重叠 |
| 响度 | 峰值 1.0397，RMS 0.3361，3 062 个削波采样点（母带压得很满） |
| 静音 | 起始 0.107 秒，结尾余音 0.021 秒 |
| 调性 | A 小调（Krumhansl–Schmuckler r = 0.479），其后 F 大调 0.323、G 大调 0.275 |
| 速度 | 128.3 BPM，置信度 0.15，竞争解 88.5 / 66 |
| 结构 | 14 个新颖度边界 → 0/15/31/44/60/74/88/104/119/134/147/163/175/193 秒 |
| 旋律 | FFT 自相关求 f0，65–1 200 Hz，带相关性门限 |
| 立体声 | 侧/中能量比（画面横向扩散跟着它走） |

**速度这个值我没有直接采信。** 检测到的乐句边界相对该小节网格平均偏差 556 ms，
而随机偏移的期望值是 468 ms（bar/4）——也就是说结构并不支持这个节拍。
但歌词提供了独立的旁证：2:27.66 起的 12 次 `EXECUTION` 诵唱间隔 0.94 秒
= 每词两拍 → 127.5 BPM，与实测 128.3 BPM 吻合。
所以画面里的脉冲不跟节拍器，而是跟从 flux 包络上实测出的 onset（全曲约 500 个），
它们与录音天然同相。

## 画面在做什么

它是一支 MV，不是频谱读数。全片发生在一间暗房里，**唯一的光源就是那张纸**：歌词说到什么，
什么就被墨线画在这张发光的纸上。纸不是贴在画框上的一张卡，而是**立在房间里的一块板**——它侧转
几度、只有一半朝向灯、把光泼在有灭点的地面上，并在自己脚下留一块影子。所以没有"背景"可设计：
只有灯、光照到的地方、光没到达的暗处，以及逆着光的剪影。

逐句对齐：通电与合闸、纸上写下的字段（`me.heart = null` 用绯红，正是那句 used before defined）、
被创建的**对象**立方体、摆开的棋子、罩住一切的 PROTECTION 穹顶、封在球里的小世界与球里的片名、
散点长出坐标轴、圆与展开的周长、可以坐上去的切线、趋近无穷的渐近线、交流整形成直流、
合上的眼睑、旋涡、被倒着擦过的时间轴、两个圆交叠、光标走向心、`> run execution` 与落下的铁栏、
一张跑起来的类型表（`switch (me.form)`：茄子/番茄/狸猫各是一个 case 的返回值，一次只点亮一个）、
内存里只剩一个实例与落在它与虚线插座之间的 PROOF 印章、♀♂ 换位、从早到晚的钟面、
S 与 M 对调、出神的同心圆、进度条走到 COMPLETION、被一条条切断的**星型拓扑**（六句"你走了"）、
删去的碎片、**被挖掉一颗心的心**（DISHEARTENED／无心）、`IllegalArgumentError` 的堆栈跟踪、
然后——房间变成判决的颜色。

`EXECUTION` 段是这张纸变成**处决令**的时刻：绯红墨、逐行点验、每判一行盖一枚朱批；
`If I can have you back` 从最后一行往上把它们逐行划掉，旁边那个插座已经空了。
之后是爱的代数式、铁栏收成心的轮廓、灯缩成一扇窗、最后一道红线、以及待机灯的一下呼吸。

逐句对齐是**审计**出来的，不是感觉：SATISFACTION 的心原先在 61.95 秒就出现了（比歌词早 3.4 秒）、
DISHEARTENED 处错放了 ILLEGAL ARGUMENTS 对话框（早 6.3 秒）。现在心落在 65.39、"无心"落在 124.89、
堆栈跟踪落在 131.22。

`EXECUTION` 段不再是红色长条图，而是**程序清单本身**：它被画成一张不透明的纸——
一份用绯红墨水写在淡色纸上的**处决令**，压在黑红底上。每诵唱一次，红字标记往下走一行，
最后落在 `throw` / `process.kill(me)` / `exit(0)` / `return you;`，每判一行盖一枚朱批。
`If I can have you back` 则从最后一行往上把它们逐行划掉。
纸牌是不透明的，这是"元素不再压住代码"的结构性保证：铁栏、剪影、字幕带都只能落在纸外。
清单只放 runtime 那 10 行——class 本体在 OBJECT CREATION 时就已经写在世界上了。

## 歌词重读：说话的就不是一个人

你提醒"主题其实没有必要是个人"之后，我把歌词逐句重读了一遍。这一读改掉的不止是道具，
因为**说话者从头到尾就不是人**——它是被创建、被填参数、被世界执行的一个实例：

| 段落 | 唱的是什么 | 读出来的是什么 |
| --- | --- | --- |
| 0–16 | Lay down your pieces / OBJECT CREATION / Fill in my data parameters | 落子的是你，被填的是我。出生之前字段就写好了，其中 `Heart heart;` 从未初始化 |
| 29.7–44 | 散点 / 圆 / 正弦 / 趋近无穷 | 四句是同一个条件句：换成任何一种数学形状，交出去的都是"定义我的那个量"。最后一句最狠——我的边界由你来给 |
| 44–59 | switch my current / gender / role，AC→DC，AM→PM，F→M，S→M | 电流、性别、位置、时间全是可赋值字段。这不是一个人换装扮，是一个对象改配置 |
| 59–74 | give you all the STIMULATIONS → be your only SATISFACTION | 一笔交易：我做你唯一的刺激源。亲密在这里已经被"可测量的量"换掉了 |
| 74–88 | 茄子 / 番茄 / 狸猫 / 唯一的神 | 排比继续，词库从数学掉到菜市场：能给的全给了。然后跳到"若我是唯一的神，你便是我存在的证据"——唯我论需要一个见证者 |
| 110.9–118 | you have left × 6 → ISOLATION | 全片的转折，而且是**拓扑**的转折：网络里六条连线按六句词一条条断，孤岛是字面意义的孤立节点 |
| 118–131 | erase the pointless FRAGMENTS / DISHEARTENED / ILLEGAL ARGUMENTS | 碎片是待回收的对象；DISHEARTENED 是 heart 这个组件被删（回指开场那句从未初始化）；"非法参数"是运行时异常，不是吵架 |
| 147–162 | EXECUTION × 12，然后 EIN/DOS/TROIS/NE/FEM/LIU | 动词从"执行"滑向"处决"。六种语言数到六，是一场多语种的宣判 |
| 162–170 | give **them** all the EXECUTION → be your only EXECUTION | 全曲最暗的一句：如果我把所有人都处决掉，就能做你唯一的刽子手。所以这里是一排节点依次被划叉，最后只剩 `me → you` 那一条线 |
| 184–191 | I know the algebraic expression of LOVE / though you are free, I am trapped | 答案就是第一段那张图：极限永远逼近、永远碰不到那条线。它把爱完全学会了，仍然被囚——知识不救命 |

于是这一轮把还剩下"人"的地方全换掉了：

- 主体从剪影的人改成一个**节点**（`G.subject`）。它的表情只有一种：是否还受光。`kneel` 是沉向地面，
  `empty` 只剩一个虚线插座，`dead` 是被划叉。
- "你还是走了"原来是窗边一个人影，现在是**星型拓扑**：一个 hub，六条臂随六句歌词逐条断开并盖红叉；
  到 ISOLATION 时 hub 仍然亮着，但已经没有可发的地方。
- "如果我是一根茄子"原来是三张标本并排（静物画），现在是一张跑动的**类型表** `switch (me.form)`：
  一次只点亮一个 case，图版是那个 case 的返回值。
- "如果我是唯一的神"原来是头顶光环，现在是内存里只剩一个实例，它与另一个虚线插座之间落一枚 PROOF——
  存在是被**指认**出来的。
- "give them all the execution" 原来是铁栏加一把刀，现在是队列里七个节点依次划叉，最后 `me → you`
  的线加粗，刀挂在这条线上。
- 宣判倒计时原来是一个人跪在大数字前，现在是六个节点，每说出一种语言就熄灭一个。
- 结尾 `love(x) = lim x→∞` 不画新图形，而是把第一段那条渐近线**原样画回来**（同一个 `G.approach`），
  并在虚线旁写回那句 `// you can be my limitations`。开场与结尾于是是同一张图的两次阅读。
- 片尾被划掉的最后一行由 `return her;` 改成 `return you;`——它要归还的从来不是"她"，是"你"。

### 可是片子还是没懂：台上没有"你"

上面那张表把结构读对了，画出来的东西却仍然是一张系统图。原因是我只翻了**她**那一半：
这首歌从头到尾是对**第二人称**说话的——有人给她填参数（"Fill in **my** data parameters"）、
她把自己每一部分当礼物递过去、然后那个人关掉了程序（"Though you have left"）。
我之前的片子里**根本没有第二个在场**，所以"你还是走了"只剩遥测栏里 `you()` 从 present 翻成 null，
"若能把你换回来"没有可换的对象。**没有在场，就演不出缺席。**

于是房间里加了第二盏灯（`companion()`，由 `room()` 在**每一镜**调用，所以它始终站在同一个世界坐标上）：

- 它不是人：大厅尽头的一盏灯 + 地上一圈粉笔线。灯在 6.38 秒（OBJECT CREATION）亮起，
  在 112.22–115.78 秒那**六句 "you have left" 期间**熄灭，之后剩下那圈线，一直留到片尾——
  那是她删不掉的唯一一件他的东西（对比 `erase all the pointless FRAGMENTS`）。
- 191 秒"though you are free, I am trapped"于是变成空间关系：**他的圈在栏子外面空着，
  她的球在栏子里面亮着**。自由与囚禁不再靠字幕说。

位置是被渲染结果教出来的，两次都错：先放 `DW×0.13`，被画框裁到只剩边上一条；再放高一点，
结果在纸移到左半的那两镜里整个藏到纸后面。只有把灯提到纸的上缘以上（`DH×0.165`），
它才在任何构图里都读成"大厅尽头的一盏灯"。

同时补上的还有两件：

1. **给，要真的给出去**（`GIVEN` 九项 + `givings()` + `companion()` 里的落点）。唱到的那一刻字在纸边
   显形，两秒后淡掉，只留一个虚线空盒；同时那个东西**从纸的左缘离开、划过房间、落进他站着的那一圈**。
   到诵唱段，纸的右缘是一列洞，而他站过的那圈里堆着八颗亮起来的小球——**她把一切都给了一个空位**。
   之前每一镜都从零开始画它的图，"给出去"这件事在片子里没有任何记忆。
   唯一没有落进圈里的是 `HEART`：它标了 `cut`，因为心不是她给的，是被删掉的（DISHEARTENED）。
   191 秒那一格因此自己说完了整首歌：圈里堆满她给过的东西，圈是空的，她在栏子里。
   （`analysis/frame-gifts-arrive.jpg`：34 / 44 / 88 / 191 秒，看那圈怎么一颗颗满起来。）
2. **SIMULATION ≡ LOVE 必须是同一个镜头**。73 秒唱 "trapped in this strange strange SIMULATION"，
   191 秒唱 "I am trapped, trapped in LOVE"——同一个句子，同一个槽位换了词。
   这两处在片子里原本毫无关系。现在 `chorus1` 与 `free` 共用一套取景、一个纸矩形、
   一组一模一样的铁栏几何、一个同位置的节点，只有填进槽位的词、以及铁栏最后显出它本来就是
   心的轮廓，这两件事不同。

## 关于中文与典故

英文是原唱，中文是我重写的，不参照原 LRC 的翻译——因为几个双关只有选对中文词才立得住：
`OBJECT CREATION` → 创建**对象**（既是实例，也是恋人）；`EXECUTION` 在前半保持"执行"、
到诵唱后半才变"处决"（执行代码与执行死刑共用这个动词）；`To AC to DC` → 由**交流**换成直流；
`DISHEARTENED` → **无心**（无情，也是 heart 这个组件被删除）；`LIMITATIONS` → 极限。

典故也换到了这首歌真正所属的脉络里（我最初误用了中文典故）：
被写上一个词才活动的**戈仑**（对应 OBJECT CREATION / INITIALIZATION，最后的 EXECUTION 就是那一笔擦除）、
**柏拉图的洞穴**（对应 trapped in this strange strange SIMULATION）、
**巴别塔**（EIN/DOS/TROIS/NE/FEM/LIU 六种语言）、**俄耳甫斯回头**（If I can have you back）。
庄周梦蝶没有进字幕——机器会把它写在日志里，所以它出现在运行控制台：
`butterfly_check: who is dreaming whom`。

### 再让画面对它负责

1. **摄影机交给节拍**：每小节内缓推、到下一小节头释放（呼吸周期就是小节，不再是各幕自定的慢变焦）；
   强拍的额外推量取自**那一拍实测的 onset 权重**，所以鼓重的段落画面自然更用力。
2. **切点吸附到小节线**：离小节线 1/4 拍以内的镜头切换一律挪到小节线上（卡点）。
3. **一条旋律线贯穿全片**（`mv/line.js`）：横向是时间，纵向是对数音高，走的就是实测 f0；

   所以这条线是"从灯后面走过去"的，和这间屋子的物理一致。每个音符的起点与终点有 0.12 秒淡入淡出，
   否则一次断音就是一帧闪屏（校验台在 50.16 秒抓到过）。

   最后拖长的 LO-O-OVE 里它**压平成一条永远走不到的水平线**——和纸上那条渐近线互为对位。
   这里返过两次工：一开始我让线去画圆、正弦、心形、星型，逐帧图一看**全废**——
   纸面上同一时刻正画着带标注的圆/正弦/心/星，一帧里出现两个同样的形状，
   正是我上一轮承诺消灭的"东西太多"。换成 PROTECTION 的罩子后**又废了一次**：
   那一镜的纸上本来就画着一只穹顶。所以判据是"纸画不了的"，最后留下三样：
   一圈闭环、判决的栅栏、以及那条渐近线本身。**纸负责论证，线负责演唱。**
4. **被唱到的大字进入画面**：歌词里那些全大写的钩子词（DIMENSION、CIRCUMFERENCE、SATISFACTION、

纸上的内容没跟着变密。修法是回到"这是一张纸"：给纸打上**格线**（16 行 7.5% 的淡墨 + 一条红色页边线）。
它不新增任何信息、不与墨线争，但一眼就能认出是纸（`analysis/frame-ruled-paper.jpg`）。

**联系表上那格死黑**。131–147 秒细节密度 14.7，全片最低。"房间没了灯"是对的，但 16 秒空黑是片子里
的洞。三下补齐：`dusk` 色板从近黑提到冷暗（`room1 #0b0e12 → #182533`、`glow #5f6f7e → #7d94ab`）；
地上那团光**压扁到地平面上**（scale y 0.3）并加亮到 0.26；跪着的节点不再只靠响度取光，改成
`0.4 + rms*0.3`——它终于被自己那团光照到（`frame-room-lit.jpg` 第 9 格）。

**最后一层平面感：地面和纸共用同一个矩阵**。`room()` 里那张地格是画在设计空间的，而设计空间整体
被 `applyCamera` 缩放平移——于是地板永远跟着纸一起动，两者永远不会不一致，而**一个"没有任何东西
在镜头运动上持不同意见"的房间，就是一张平图**。把大厅搬到 `mv.js` 的 `drawRoom(t, cam)`，画在
**屏幕空间**、在纸的相机矩阵之外：灭点跟着 `cam.x` 走、地平线跟着 `cam.y` 与 `cam.z` 走、横向光带
的相位由 `cam.z` 驱动（推镜头时它们朝镜头滑过来）。`room()` 只留下属于纸的那部分——地上的光池与
接触阴影——它们跟着纸走，正好说明纸是**站在那个房间里的一件东西**。
两处按渲染结果收的口子：天空与地面在 `hy` 处必须交于**同一个颜色**，否则画面上出现一道硬接缝；
扇形线从 0.3 降到 0.13，全强度时它在纸后面炸成一朵星芒，抢过图。

**运镜：让摄影机真的横向走位**。地面搬到屏幕空间之后，才终于可以做一件之前做了也没意义的事——
一个每八个乐句走完一次的横移（`cameraFor` 里 `sin(2πt/15s) × DW×0.055`）。之前整幅画共用一个矩阵，
左右平移只是把图挪一挪；现在纸按 1 倍响应 `cam.x`、大厅按 0.55 倍，两者一错开，镜头一动就是
"摄影机在房间里走"。量出来的效果：66 / 69 / 72 秒三帧，纸的左缘从 0.166 → 0.198 → 0.133 幅宽
（`analysis/frame-truck.jpg`）。漂移加在平滑状态**之后**、且不回喂，否则它会自己叠加。

**铁栏收到纸的尺寸**。横移把 72 秒那一镜的另一处毛病照亮了：`Though we are trapped` 的铁栏是按
**房间**画的（从画面顶到地面、宽 992），于是它是一排红色栅栏立在镜头前面，正好唱反调。改成按
**纸**画（顶到 `L.y - 40`、底到 `L.y + L.h + 22`、宽 `L.w × 1.34`、5 根、线宽 6 → 5）：
现在看得见的是几根从纸上方和下方探出来的栏，铁笼是被推断出来的，而不是挡在画面前的（`frame-cage-sized.jpg`）。

**这一轮结束时重扫 25,429 帧：0 未归因闪现**（22 个尖峰＝10 溶解 + 12 硬切），flags 69 → 67。
横移把运动均值抬高了一档（主歌 0.5 → 0.6、开场镜头速率 0.4 → 1.7），这是买视差的钱，仍然远低于
任何会被眼睛读成抖动的水平。顺带白捡的两格亮度：开场 `minLum` 19 → 32、间奏 55 → 66——
地面本身带颜色之后，镜头不再从一块纯黑开始。

## 第七次：premise 在画面上是假的——那张纸根本不发光

连着几轮我都在给画面加东西：透视、体积、光池、走位、第二个在场。某一次终于把一帧按 2400×1350
放大来看（之前一直看的是 480–960 的联系表格子，那正是漏掉问题的分辨率），发现**全片的立身之本是谎话**：
README 写着"房间唯一的光源就是那张纸"，可那张纸是一块**灰色 MDF**——最亮的一档只向白偏 20%，
最暗一档向房间色偏 74%，bloom 只有 0.15。它不发光。之前所有打光与透视，都只是在给一块不发光的东西补光。

| 改了什么 | 之前 → 之后 |
| --- | --- |
| 纸成为**自发光体** | 近角允许过曝（向白 66%），墨线改成"逆着光源的剪影"而不是白板上的线图；纸下加一层 `lighter` 热区；bloom 0.15 → 0.34 并放宽；地面光池 0.16 → 0.40——**由别的东西来证明它在发光** |
| 那盏灯去掉硬边 | 原来是一条 `fillRect` 半透明带，等于"光有直边"；改成压扁成 0.3 的径向渐变，光柱没有边 |
| 墨是**写上去的**，不是矢量 | 所有描边原语（`line/ray/poly/circle/box/sine/approach/heart`）走同一个 `inkStroke`：同一条路径先以 2.5 倍宽、15% 透明度描一遍（笔尖在纸上的洇），再以原宽描一遍。整部片子的"手"一次换掉 |
| 旋律线退让 | 0.62 → 0.44，它之前在画面正中像一道栅栏 |

量出来的下限全线抬升：主歌最低亮度 **79 → 101**、**83 → 107**，副歌 **74 → 94**、**74 → 97**，
判决段 **73 → 90**，揭示段 **60 → 76**，间奏 **61 → 75**；各幕最低饱和度同样上涨（开场 39 → 46、
片尾 89）。也就是说：分幕色板现在是真的在**承载光**，而不是被照成一片灰。

证据：`analysis/frame-emitting.jpg`（56.9 秒，发光但墨还没改）、`analysis/frame-ink36.jpg`
（36 秒，马克笔洇开之后）、`analysis/frame-emit-four.jpg`（四格对照）。

## 第八次：全片没有剪辑节奏，也从来没有特写

联系表看完，下一个短板不在光，在**剪辑**：~20 个长镜头用溶解连起来，每一个都是"一张纸立在画面
正中"的同一个中景。可这首歌是 128 BPM 的戏剧性曲目，小节与小节之间的冲击强度差出一倍以上。
也就是说：**画面根本没有在跟音乐剪辑，只是在跟着音乐呼吸。**

于是加了一个从实测数据里长出来的剪辑层（`mv/mv.js` 的 `CUTS`）：

- 取景变化的候选时刻**只能是实测的拍点**（`M.beat`），不是我自己定的时间；
- 允不允许切，看这四拍被击中的力度（`M.beatOn` 的均值）：`e < 0.28` 不切，`e > 0.55` 允许切在半拍上，
  否则只在强拍切；两次切之间至少隔 1.0 / 2.4 秒，随能量走；
- 声明了 `cut: true` 的诵唱段整体跳过——那一段本来就自己会剪；
- 三种取景轮换：镜头自己的中景、**把墨填满画面的微距**（`z × 2.35`，对准 `page()` 公布的纸矩形）、
  以及退一步看见房间的拉远（`z × 0.72`）。微距是全片从来没有过的东西。

结果：46 个剪点，逐帧扫出 32 个尖峰归为新的 `beat-cut`。

**闸门不能靠我自己发牌。** 加 `beat-cut` 这个归因时，判据必须是可查的，不然就等于把不喜欢的
尖峰改名成合法的。所以现在要同时满足两条才算：尖峰与公开剪点表 `window.CUTS` 里的某一项在 2 帧
之内重合（那张表只可能由实测拍点生成），**并且**那一帧摄影机确实不连续地跳了（`pdx + pdy > 40`）。
元素凭空出现而摄影机没动，仍然是 `FLASH`。剪点表挂在 `window` 上，就是为了这条判据可以被复核。

修掉的三个真 bug（都是被这轮扫描逼出来的）：

| 时间 | 症状 | 根因 |
| --- | --- | --- |
| 85.075 | 整页内容一帧之内从类型表换成"唯一的神与见证者" | `if (t < 85.07) {…} else {…}` 是硬分支；改成 0.55 秒交叉淡入 |
| 124.892 | 遥测 `heart()` 一帧之内从 `uninitialised` 变成 `null` | 离散状态直接换字；改成换值前先淡出、淡回（每帧都在变的实时读数不参与） |
| 47.675 | 大字的第一个字在一帧之内凭空出现 | 裁剪带写成 `left + 12 + tw*u + 4`，`u=0` 时已经露出约 16 像素；改成从 `left - 8` 起算 |

证据：`analysis/frame-macro.jpg`（四个微距镜头）、`analysis/frame-edit-sheet.jpg`（14 格联系表，
微距/中景/拉远第一次同时存在）、`analysis/frame-xfade.jpg`（47.9 与 125.1 两个交叉淡入的中间态）。

**改完重扫 25,429 帧：0 未归因闪现**（67 个尖峰＝32 `beat-cut` + 21 溶解 + 14 硬切）。
代价说清楚：`flags` 从 67 涨到 111，全片运动均值涨到 0.5–1.1——这不是失控，是剪辑本身的代价，
每一个 `beat-cut` 都是一次摄影机的不连续。所以这一轮同时把 29 处硬分支里真正产生尖峰的那几处
改成了交叉淡入，其余 27 处是**同一类潜伏缺陷**，记在这里而不是藏起来：任何一处被观众看见，
就会以 `FLASH` 的形式回到这张表上，判据已经在那儿等着它。

## 第九次：真的按帧去看——1080P、360fps、连续取帧

被要求"自己完整地用 1080P 以 360fps 向屏幕截图并依次分析"之后，加了两个**不摘要**的工具
（`analysis/verify.js`）：

- `VERIFY.burst(t0, n, name, rate)`：连续取 n 帧，逐像素保留"相邻两帧之间它变过多少"的最大值，
  出一张热图 + 分格数字；
- `VERIFY.strip(t0, n, name, rate, cols)`：把这 n 帧**原样拼成一张 1080P 的条带**，标上毫秒偏移，
  让人真的去读序列。之前所有工具都在把画面压成标量，而标量会藏东西。

### 看到的第一件事：画面几乎没在动

同一时刻用四种帧率测"相邻帧平均逐像素变化"（0–765 求和）：

| 取样率 | 每帧平均变化 | 变化 > 24 的像素占比 |
| --- | --- | --- |
| 360 fps | 0.63 | **0.32%** |
| 120 fps | 1.68 | 0.64% |
| 30 fps | 6.00 | 1.74% |
| 8 fps | 14.14 | 4.68% |

它随 dt 线性缩放，所以**不是噪声，是真的没东西在动**：相邻两帧之间 99.7% 的画面是静止的。
我此前一直把"运动均值 0.5"当成优点（画面稳、不闪），它实际的含义是**一张缓慢变焦的照片**。
这条判据只有按帧看才能得到——全片汇总的指标里它是最好看的数字。

### 于是让摄影机真的穿过房间

`cameraFor` 里加了乐句级走位：每四个小节（7.5 秒）走完一次 `sin(u·π)`，摄影机横穿房间宽度的 10%、
推进 20%、抬高 3.5% 房间高度、并带 1.3° 的滚转；相邻乐句交替方向，`sin` 在两端都是 0，所以接缝连续。
滚转同时作用于大厅（带 1.06 过扫描遮住转角），否则地平线水平而纸在斜，读起来是"物体歪了"而不是
"摄影机在动"。

### 第二件事：微距把杂乱放大了

360fps 条带（`analysis/frame-seq-macro.jpg`）读出来的是：推近之后，账本的灰盒子、遥测文字、虚线、
红叉、尘埃和图元处在**同一种视觉重量**上，特写里没有可看的焦点，右侧还留一条只有淡字的死带。
真实摄影机推近时画面会变简单，所以：`window.EDIT` 把当前取景模式告诉所有层，
**微距段里尘埃、账本、遥测面板全部退场**，微距倍率从 2.35 降到 1.85（再高就只剩纸的纹理）。

顺带记一个按帧才现形的假象：36 秒那一处曾测到每帧变化 4.39，比 120fps 的 1.74 还大——平滑运动不可能这样。
差分图（`analysis/frame-diffmap.jpg`）显示亮的**全是纸的横线**：那是细光栅在放大倍率下与像素栅格打拍，
是伪运动。降倍率之后同一处回到 1.35。**指标把光栅闪烁当成运动能量奖励给我看了**，这类东西只能靠看图分辨。

### 全片 360fps 重扫的结果

`VERIFY.start(360)`：**76,287 帧、0 未归因闪现**（66 个尖峰＝33 `beat-cut` + 25 溶解 + 8 硬切），
flags 101。亮度下限与上一轮 120fps 对照全线抬升：开场 19 → 60、`dusk` 39 → 65、片尾 36 → 67、
主歌 79/83 → 106/123——这是"纸开始发光"与"摄影机开始移动"两件事一起的结果。
`analysis/verify-360fps.png` 是这一轮的曲线图（文件名跟着扫描速率走）。

### 每镜头"一小节内变化率"：把最死的段落排出来

按帧看之后加了逐个镜头的测量：每个镜头取若干时刻，比较 `t` 与 `t + 一小节(0.469 s)`，
统计平均逐像素变化（0–765）与变化超过 24 的像素占比。全片排序，最差的两段是**结尾**：

| 镜头 | 一小节内平均变化 | 变化像素占比 |
| --- | --- | --- |
| `final`（205.8–211.9，最后 6 秒） | 6.9 | **3.2%** |
| `void`（131.2–147.7） | 13.1 | 16.1% |
| `powerdown`（193–205.8） | 34.6 | 22.5% |
| 对照：`count`（诵唱数数） | 97.8 | 44.9% |

也就是说：**观众最后看到的 19 秒是全片运动最少的地方**，而它偏偏是决定"这趟值不值"的位置。

### 一次失败的修法，和它教的东西

先试的是"让光变暗"：给 `void` 的光池加衰减、把 `powerdown` 的纸面改成一条**边界扫过**的渐变。
量完的结果是 `powerdown` 从 34.6 **掉到 8.6**、`final` 从 6.9 掉到 4.3。原因很干净：
**在近黑的画面里，透明度变化几乎不产生像素差**；而边界扫过的只是一块小板子的边缘，面积太小。
`powerdown` 那处改动已撤销，注释里写下了撤销的理由和数字。

真正的因不是"缺动画"，是**缺光源**。能在大面积上产生变化的只有一件事：**一个亮的东西在画面里改变大小**。
所以结尾改成：摄影机一路后退（`z` 从 1.2 退到 0.7），纸上留一颗**还亮着的心**，
最后一个 `EXECUTION`（205.81 秒）落下时整间屋子泛一次红，那条红线画出来之后**倒着收回**——
机器状态栏从 193 秒起一直写着 `REWINDING`，结尾就该是倒带。

`void` 那处则让光池**边收缩边变暗**（边界扫过地面，面积大）：13.1 → **29.0**，16.1% → **37.9%**。

证据：`analysis/frame-ending-rewind.jpg`（205.9 秒起每秒一帧，红潮退去、大字逐字擦出、
红线画出又收回、她的纸越来越小但一直亮着）。

全片 360fps 重扫（76,287 帧）：**0 未归因闪现**，62 个尖峰＝33 `beat-cut` + 22 溶解 + 7 硬切。
`final` 那一镜现在每秒都在变东西，但它的"一小节内变化率"仍然只有个位数——因为它整段就是一盏
越来越小的灯，这是**选择**的静止，不是没内容的静止；区别在于这一次画面里有光、有运动的方向，
而观众知道那是什么。

## 第十次：把每一格打出来看，才发现摄影机根本没对准主体

第九次量的是"画面有没有在动"。这一轮换了一个问题：**画面里那个该被看见的东西，在不在框里。**

### `study` 那一镜，纸上是空的

177.24–184.54 唱的是 "I've studied, I've studied how to properly LOVE / question me, I can answer all"——
全片她唯一一次**赢**。逐格打出来看，这张纸上是：一条细曲线，和一片糊成白的纸。
于是两件事：

1. **把演算铺满纸**。`love : X -> Y`、`dom(love) = me`、大红 `LOVE`、`d/dx love(x) > 0`、
   `int love dx -> oo`、`Q: how much?` / `A: everything`——一行行按她唱到的拍子弹出来。
   第一行放在 **177.30**，也就是镜头切进来之前纸上就得有字。
2. **纸不许过曝**。`page()` 的白场收紧（0.66/0.30 → 0.62/0.22）、中段往 `col.glow` 偏 0.34、
   远端往 `room0` 偏、高光半径的 `lighter` 从 `0.3 + lum*0.18` 降到 `0.18 + lum*0.12`。
   182 秒那一格现在带**房间的暖色调**，而不是一张白纸。

证据：`analysis/frame-study-working.jpg`（2400×1350 实拍单帧）。

### 真正的病根：主体在画框外面

把 `study` 整段连续取帧排成一张表，看到的不是"纸不够满"，是**纸被钉在画面左缘、右半格全是空屋子**。
这不是某一镜的疏忽——加了一个新的检查 `VERIFY.framing()`（把每个镜头按 0.25 s 采样，
用渲染器同一套投影，量纸心与相机 x 的偏差，并**扣掉入画那 0.7 秒**——相机滑向主体是运动，不是画框错了）。
指标是"稳定段里，纸出框最惨时占它半宽的比例"。基线：

| 镜头 | 稳定段最惨出框 |
| --- | --- |
| `left` | **113%** |
| `current` | **104%** |
| `geometry` | 89% |
| `free` | 81% |
| `study` | 57% |
| `give` | 36% |
| **全片均值** | **58%** |

16 个带纸的镜头，**每一个都有出框的采样**。落到画面上就是：`LOVE` 显示成 `OVE`，
`// you can be my limitations` 显示成 `he my limitations`，`Q: how much?` 只剩 `much?`。

原因很干净：每个镜头**各自**写摄影机目标 `x` 和纸的矩形 `L`，两边没人对齐。
`study` 的目标是 `DW*0.5 = 800`，纸心在 `300 + 700/2 = 650`——作者就把相机摆偏了 150；
乐句行进 `arc*DW*0.1 + drift` 最多再加 196。加起来，主体就走出去了。

### 一处约束，而不是 16 处补丁

没有去逐个改 `frame()`，而是在 `cameraFor()` 末尾加一次 `boundToSheet()`：
**相机可以看漏一张纸的一角，但不许把它拦腰切断。**
12% 的溢出是留给"真特写"的——一个填满画面的字本来就该出框。

写第一版时错得很有代表性，三个都是量出来才发现的：

- **平滑了错误的东西。** 先平滑"偏移量"，于是推镜头跑得过快、限制追不上：
  `give` 在 161.7 秒有小半小节，纸**出框 104%**。
- **改成平滑"矩形"，又绑到了旧纸。** 换镜时 `cx` 的跳变确实被抹平了，代价是相机改成照着
  **上一帧那张纸的纸心**去框：叠化期间两张纸的纸心差 180 设计像素，于是它夹的是一个不存在于画面里的位置。
- **两个分支写反了。** 注释里写的是"跟着动的主体要跟死、跨镜的跳变要抹开"，
  代码做的正好相反。判据最后落在**镜头身份**上：同一镜内（含纸自己滑动的 `chant`）硬夹，
  换镜那一帧才走缓动。

判据本身也先错过一次：最早那版指标量的是"相机偏离纸心多少 / 半幅"，
于是它把**额度**当成了**缺陷**——同一个改动，它报出"平均偏差 6.3% → 32.4%"这种毫无意义的数字。
现在拆成两个数：`lateCutPct` 量"有多少纸真的在框外"，`worstOverPct` 量"越过了额度多少"。

还有一个是顺带挖出来的：叠化期间 `render()` 会**同时画两个镜头**，入场镜头的 `page()` 会把
`window.SHEET` 覆盖掉——于是特写套到的、相机自我约束所参照的，是那张**只占 30% 透明度的幽灵纸**，
相机在叠化中途横跳一次。`render()` 现在在入场镜头画完后把矩形还原。

### 留在框里 ≠ 框好了——以及一次过头的修法

夹上之后再打表：纸不切了，但 182 秒那一格，整张纸**完整地位于画面左 40%**，右边 55% 是空屋。
因为限制只回答了一个问题——"最多能让主体漏出去多少"——它不关心主体在画面**哪个位置**。

于是先加的第二项是：主体偏离画面中心不得超过半幅的 16%。
**指标立刻变好**（全片均值 58% → **5%**，`study` 57% → 0%），所以我把它写进了上一轮。

然后把它**撤了**——因为把 `chorus1` 逐格打出来看，那 15 秒的机位被钉死了。
`chorus1` 的纸在 `x 470`，而它的铁栏在 `DW*0.8 = 1280`、主体在 `DW*0.86 = 1376`：
这是一个**两张纸之间夹着一个人的双人镜头**，作者故意把相机摆在中间偏右。
16% 的约束要求相机贴住纸心，于是把它的横向行程（`arc*DW*0.1 + drift`，最多 196）整段削平，
画面里剩下的只有光标、涟漪和心——**运镜没了**。指标从没告诉我这件事，因为"出框"这个量
根本不包含"构图"这个维度。

教训写进代码注释里，免得有人再把它加回来：

> 主体**在不在**框里是正确性，相机可以自己判；主体**该不该**在这儿是创作决定，只有那个镜头知道。

`study` 的偏心于是改在它自己家里：三段 `frame()` 的 `x` 从 `DW*0.5`（800）改成纸心 **650**。
改完 `study` 的稳定段出框 **0%**，纸在九格里都在中间，而 `chorus1` 的机位回来了。

| 镜头 | 不夹 | 加过心的约束（已撤） | 撤掉、改作者自己写对 |
| --- | --- | --- | --- |
| `study` | 57% | 0% | **0%** |
| `chorus1` 的运镜 | 有 | **没了** | 有 |
| **全片均值** | **58%** | 5% | **11%** |

那个 11% 里含 `powerdown`/`final` 的换镜那一帧——限制在那里走缓动，是**跨**而不是**切**，
出框量按 150 像素宽的小纸算会显得很大，逐格看时纸是完整的。

证据：`analysis/frame-twoshot-pinned.jpg`（加了心约束的 `chorus1`，12 格——纸几乎不动，
机位是锁的）与 `analysis/frame-twoshot-travelling.jpg`（撤掉之后，8 格——纸从中间走到左边再回来，
色温从蓝走到琥珀）。这两张是撤掉那条规则的直接理由。

另有：`analysis/frame-framed-before.jpg`（不夹）与 `analysis/frame-framed-after.jpg`（现在这版），
同一段 178.2–189.2 秒、每 1.33 秒一帧、九格一张。后一张里 `LOVE`、
`Q: how much?` / `A: everything`、`// you can be my limitations` 全部完整，且九格里纸都在中间。

### 全局改相机之后必须重扫

`boundToSheet()` 动的是每一帧的 `cam.x`，所以它是**全片级**改动，不能靠抽帧验收。
1080P / 360 fps 全片重扫（76,287 帧）：**0 未归因闪现**；
72 个尖峰 = 33 `beat-cut` + 24 溶解 + 15 硬切，全部有出处。

这一轮还顺手确认了那个指标的一个**盲区**：`chorus1` 这一幕的"平均逐像素变化"是 **0.0**、
峰值只有 31（全片最低），但逐格看它其实**在演一件事**——光标移过去、点一下、涟漪一圈圈散开、
心被画出来、`> run execution` 出现、色温从蓝走到琥珀。原因很直白：这些全是**大亮页面上的细线条**，
面积太小，摊到整幅像素均值上就没了。同一张表里它的 `pan` 是 1.5，说明相机确实在走。
所以"出框率/变化率"这类**面积加权**的量，只能用来抓"整块画面错了"的毛病
（切主体、空半幅、锁机位），不能用来判"这一幕有没有在演事情"——那还得一格一格看。

## 第十一次：眩光把这一镜要说的东西吃掉了

`switches`（88.6–110.9）缩略图里有一道"左边发亮的竖条"，看着像渲染错误。放大到 2400×1350 单帧看：
那道竖条是纸自己的左缘，没问题。**但同一格里有真的毛病**——纸的左上角糊成一团死白，
而这一镜画的是**一圈圈散开的声呐涟漪**，最外面那几圈正好死在那团白里。

也就是说：不是构图错了，是**光把内容擦了**。

### 方向反了

`page()` 里两处高光都是随房间亮度**递增**的：

```js
g.fillStyle = rgba(col.page, 0.34 + col.lum * 0.2);   // 投影光晕
hot.addColorStop(0, rgba(col.page, 0.18 + col.lum * 0.12)); // 纸面热区
```

写的时候的逻辑是"房间越亮，纸越该发光"。但会**过曝**的恰恰是已经亮的房间：
`story.js` 里 `lum` 从 0.16 排到 0.86，最亮那一档 `lum=0.86` 时热区 alpha 到 0.283，
叠在本就接近白的纸面上直接削顶。而 `lum=0.16` 的暗场里，纸是画面唯一的光源，
它需要的是**更亮**，不是更收。

所以把方向翻过来，让高光随房间亮度**递减**：

```js
g.fillStyle = rgba(col.page, 0.44 - col.lum * 0.16);  // 0.414(暗) → 0.302(亮)
hot.addColorStop(0, rgba(col.page, 0.26 - col.lum * 0.15)); // 0.236(暗) → 0.131(亮)
```

白场起点 `0.62 → 0.56`、次级 `0.22 → 0.19`。

### 两头都要看，因为 premise 只有一句话

这条改动同时碰着本片最要紧的那个主张——**纸是光源**。只验亮场会把它改弱，只验暗场会留着过曝。
所以取 `lum` 的两端各打一张 2400×1350 实拍：

- **亮端 99.79 秒**（`lum=0.86`）：涟漪从中心一直数到纸的左上角，最外两圈灰环和红环都回来了，
  而纸仍然是画面里最亮的东西。见 `analysis/frame-glare-before.jpg` / `analysis/frame-glare-after.jpg`。
- **暗端 209.6 秒**（结尾）：黑hall里那张纸**照样在发光**——暖白芯、地面接触阴影、
  纸上的心、上方正在倒着收回的红条。见 `analysis/frame-ember-heart.jpg`。

暗端的光晕 alpha 其实比改动前**更高**（0.372 → 0.414），因为 `lum` 小。
也就是说这次改动不是"把光调暗"，是**把光从不需要它的地方挪到需要它的地方**。

### 重扫报了 2 个未归因闪现，我追下去，结论是它不是闪现

`page()` 是全片 16 个带纸镜头共用的，所以这处改动照样跑了完整重扫。
1080P / 360 fps、76,287 帧：尖峰 80 个（33 `beat-cut` + 24 溶解 + 21 硬切），
但**多出 2 个 `FLASH`**，都在 `switches` 的 103.972 / 104.089 秒。

我没有直接去放宽闸门，而是先查。查的过程里**猜错两次**：
先怀疑是相机被新加的边界来回夹——实测相机完全平滑（`dx` 恒为 0.3/帧、`dz` 恒为 -0.0002）；
再怀疑是热区对每帧亮度太敏感——把斜率从 0.15 降到 0.10，结果差异图**反而略微变差**
（均值 10.8 → 11.7），于是把这两次降斜率**撤回**，只保留视觉上验证过的那版。

真正说明问题的是直接量帧。第一版量法有个索引 bug（拿 `prev[p/4]` 去比 RGBA 跨距的数组），
量出来的 93.9 是图像方差不是帧间差；修好之后：

| 位置 | 帧间平均变化（0–255） | 平均亮度步进 |
| --- | --- | --- |
| 被点名的 103.972 | 0.57 | ≤ 0.3 |
| 安静段参照 | 0.33 – 0.40 | — |
| 结尾参照 | 0.41 – 0.49 | — |

也就是说被点名的那一帧只比环境噪声高**一半**，而亮度根本没跳——**闪光是亮度跳变，它没有跳**。
差异图也印证：热的是那条又粗又黑、正在扫过纸面的正弦曲线本身，那是这一镜在演的内容。

结论记在这里而不是改代码：**闸门的 `over: 7` 离"满幅颗粒 + 一条粗曲线在动"的环境水平太近**，
所以它会把普通动画误判成孤立尖峰。我没有给它加"亮度没跳就不算闪"的豁免——
那等于在我自己想要的方向上调判据。这 2 个 `FLASH` 保留为未归因，附上上面的量法与数字。

## 第十二次：把整片摊成一张联系表，最长的白气球露出来了

前几轮都是"某一镜逐格看"。这一轮改成**先看全片**：重扫时顺手导出两张 1 秒/格的联系表
（`analysis/frame-contact-a.jpg` 是 0–105 秒那半）。摊开看立刻有一处不对劲——

**16–29 秒连续 13 秒是同一个东西：一颗灰白的球。**

放大到 2400×1350 逐格确认（`analysis/frame-globe-balloon.jpg`，2.5 秒/格）：相机确实在推近，
但球面上**没有任何能证明它是曲面的东西**。它有明暗、有 terminator、有外圈辉光，
可是亮部占了画面六成、是一片从白到灰的渐变，中间写着小小的 `world.execute (me) ;`。
再加一条**横切球体的矩形光带**（原来是 `fillRect` 画的），整颗球看起来就是
**一只吹起来的气球上贴了条胶带**。

### 球要像球，靠的是缠在它上面的东西

渐变只告诉你光在哪，**只有绕着表面走的东西才告诉你表面是弯的**。所以给世界上了经纬网：

- **纬线** 5 条，每条的半宽 `r*cos(lat)`、竖压 `0.17`，越靠极点越扁。
- **经线** 6 条，半宽 `r*|cos(经度)|`——**转到侧面就压成一条直线**，这正是"球"的判据；
  透明度也随 `|cos|` 走，转过去就淡。
- **表面节点** 11 颗，按正交投影贴在球面上（`x = r*cos(lat)*sin(lon)`，
  `y = cy + r*sin(lat) + 纬线椭圆在那一点的偏移`），背面（`cos(lon) < 0`）不画。
- 转速挂在拍子上：**四小节转一圈**（`spin = t*TAU/7.5`，128bpm 下正好 16 拍），
  于是这 13 秒里球是**在跟着鼓转**的，不是被打着光的静物。
- 那条矩形胶带换成**边缘暗角**（径向渐变，中心透明→外缘 `room0` 0.5），
  让球有厚度而不是有腰带。

### 一个只有放大才看得见的意外

第一版渲染出来，两颗节点不偏不倚落在 `execute` 正上方、左右对称——
**拼成了一个假变音符号 `ë`**。缩略图完全看不出来，2400 宽一眼就看见。
标题是这个世界上唯一必须读得懂的东西，于是加了一条避让：落在标题带内
（`|y - 标题y| < 52` 且 `|x - 中心| < 0.72r`）的节点不画。

改完（`analysis/frame-globe-mesh.jpg`）：球是球了——网格缠得住、节点在表面爬、
明暗有 terminator、`world.execute (me) ;` 干净地压在赤道上，
而那颗代表"我"的黑点仍然站在球心下方。

### 这次面积够大，指标终于跟得上眼睛

上一轮刚记下"面积加权的指标抓不到细线条的事件"。这次改的正好是**大面积**，
所以指标动了——15–29.7 秒这一段（`interlude`）：

| 量 | 改前 | 改后 |
| --- | --- | --- |
| 细节 `detail` | 30.6 | **53.3** |
| 平均运动 `motion` | 0.1 | **0.3** |
| 运动峰值 `motionMax` | 75 | 89 |

**但因果要摆对**：不是为了让指标动才画网格。是逐格看发现它是白气球，改完之后
顺便发现"这次连面积加权的量都动了"——反过来说，一个改动如果连大面积指标都不动，
那它多半是在动细线条，那种改动**只能靠眼睛判**。

### 重扫：1 个未归因，仍然不改判据

1080P / 360 fps 全片重扫（76,287 帧，835 秒）：尖峰 83 个
（33 `beat-cut` + 23 溶解 + 26 硬切），**1 个未归因 `FLASH`** 在 `void` 的 134.622 秒，
峰值 8——闸门阈值是 7，它只高出 1。上一轮那 2 个 103.97 秒的误报这次没再出现。

按上一轮定下的规矩：**不在自己改动的同一轮里为了清零去动判据。** 这个 8 留在未归因里，
连同"阈值 7 离颗粒地板太近"这条一起记着。

## 第十三次：全片最糊的八秒，和一个我亲手种下的幽灵

按"细节量"排序，全片最低的两幕是 `dusk`（16.1）和 `outro`（17.5）。
`dusk` 里只有一个镜头：`void`（131.22–147.66）。逐格打出来看，
**136.5–144.5 秒连着八秒是同一团糊在画面中部的浅色横带**——没有纸、没有字、没有人，
看着像失焦废片，不像设计出来的空。

### 两个原因，第二个是我自己造的

**原因一：光池没有边界。** 池子是一个 `scale(1, 0.3)` 压扁的径向渐变，
alpha 只有 `0.26`、外缘一路软到 0；跪着的那个节点半径 27 设计像素、`kneel` 还额外把亮度乘 0.55。
于是一大片软光 + 一个小黑点 = 一团糊。**一片光要读成"地上的水洼"，得有一个能站进去的核心
和一条能跨过去的边。** 于是：核心 alpha 抬到 `0.62`、衰减收紧（0.3 / 0.68 两段），
补一条**硬边椭圆**描池沿，幸存者从 1.0 放大到 1.9。

**原因二：`window.SHEET` 是个幽灵。** `void` 在 135.55 把崩溃报告拿走之后**再也不画纸**，
可是 `window.SHEET` 里还留着那张纸的矩形——十二秒前的东西。有两个人在读它：

- **剪辑器**：`edit mode 1` 的特写会 `x = S.x + S.w/2`、`z *= 1.85`——
  于是它**对着"报告曾经在那儿"的空地板推成特写**；
- **上一轮我加的相机约束**：把 `cam.x` 夹到那张不存在的纸心附近。

最讽刺的是：约束夹住相机别跑偏，**反而**误打误撞把幸存者留在了画框里；
真正把他推出画面的是剪辑器那个幽灵特写。也就是说，我上一轮修好了 16 个镜头的取景，
代价是给所有"纸已经不在了"的镜头留下一个隐形的锚点。

修法是一个共用的一致性检查：`page()` 每次画纸都会盖时间戳，
`sheetNow(t)` 只认 **0.5 秒内**盖过章的矩形，过期就当没有。剪辑器和约束都改成走它。

### 顺手抓到：我的量法把被测对象关掉了

改完之后 `framing()` 报"稳定段出框均值 28%、然后 54%"，看着像大回归。
实际是**指标自己把约束关了**：`framing()` 在每次采样前写 `SHEET_T = -1` 用来判断"这一帧画没画纸"，
而相机做决定时读的正是同一个章——哨兵一写，约束每帧都判"矩形过期"，直接不生效。
另外那个过期阈值也不能低于采样步长（`framing` 用 0.25 s 采样，阈值一度写成 0.1 s，
等于在扫描里永久过期）。

哨兵删掉、阈值提到 0.5 s 之后，量出来的数是这样的：

| 量 | 修幽灵之前 | 修幽灵之后 |
| --- | --- | --- |
| 稳定段出框均值 `meanLate` | 11% | 11% |
| 越过额度的镜头数 | 6 | 5 |
| `free` / `give` 越额度 | 69% / 34% | 31% / 15% |

**但这里有个必须写下来的陷阱**：`meanLate` 一点没动，不是因为这个修复没用，
而是因为**这个指标看不见幽灵**——`framing()` 拿来做判据的矩形，和相机用来做约束的矩形，
是**同一个** `window.SHEET`。锚点是假的，量"相机有没有贴着锚点"就永远是对的。
所以这个 bug 只可能从画面上发现（幸存者不在框里），量不出来。

证据：`analysis/frame-void-smear.jpg`（改之前，九格里 4 格根本没有主体）
与 `analysis/frame-void-survivor.jpg`（改之后，九格全都有：黑点稳稳坐在带硬边的光池里，
池子一路收缩，最后一格转红）。

### 重扫：未归因闪现回到 0

1080P / 360 fps 全片重扫（76,287 帧，2176 秒）：尖峰 65 个
（28 `beat-cut` + 24 溶解 + 13 硬切），**未归因闪现 0 个**。

## 第十四次：所谓"剪辑系统"从来没有剪过——它只是把画面永久改了一次

## 第十六次：用户截了一小块图丢回来——那条"旋律线"根本不成立

### 查代码：是我自己把它打碎的

`mv/line.js` 的 `melody()` 里，断线有两个条件：

```js
if (!p.live) { flush(); continue; }                      /* 检测不到音高就断 */
if (run.length && (Math.abs(p.a - ...) > 0.12 ||         /* ← 元凶 */
    Math.abs(p.y - ...) > H * 0.03)) flush();
```

第二条是我当初写的，注释还理直气壮："大于四度的跳进不是滑音，是两个音，断开"。
**可是跳进恰恰是旋律最有辨识度的部分。** 在 900 采样的压缩窗口里，这条规则把一条唱腔
剁成了几十个 2–4 采样的碎片，每个碎片还各自带一份 alpha。
所以它不是"旋律线"，是**一地旋律的尸体**。

再加上那条基准线（`rail`，音高静止时的位置）alpha 只给到 `0.1`——
那不是一条线，是一条线的传闻。传闻没法给形状当参照。

### 改了两处

1. **只有静音才断线。** 跳进连着画，于是它重新是一条会抬起来、会落下去的连续轮廓；
   长音自然形成一段平台，这正是"有人在唱"的形状。
2. **把基准线画实**（`0.1 → 0.26`），并在音域顶端补一条 `0.1` 的上界，
   让折线有一个" resting 面"和一根"天花板"可以量。

改后（`analysis/frame-melody-continuous.jpg`，160 秒同一处）：左边那条线现在是
**一条从画面外穿进来的连续折线**，抬升—平台—跌落—再抬升，底下压在一条看得见的基准上。
`analysis/frame-melody-104.jpg` 是另一个色板（暗红）里的同一处，表现一致。

### 方法上记一条

以后每轮**至少截 3 个元素级局部**（旋律线、遥测栏、颗粒/暗角这类"背景层"），
不能只看整帧。整帧会把"存在感低的元素"直接豁免掉，而它存在感低本身往往就是问题。

## 第十八次：全片最长的一段纯音乐，纸上摆着一个什么都不是的方块

死区指标的第二个点名对象是 `powerdown`（196–204 秒，23–28% 空）。
放大看，四周的黑是暗室该有的黑，**真正的问题在纸正中间**：

`analysis/frame-powerdown-pane.jpg`（200 秒）——纸上是一个**被十字分成四格、中心一小块更亮的方框**。

### 为什么这是全片最刺眼的一处

先确认它有多重要：查 `lyrics.js`，**193–205.81 秒整段没有任何唱词**（下一句是 205.81 的
`EXECUTION`）。也就是说这是**全片最长的 13 秒纯音乐**，而那张纸上唯一的东西就是这个方块。

再看它周围的邻居都是什么：`world.execute(me);` 的**代码**、`C = 2πr` 的**圆**、
`love(x) = ∫…` 的**推导**、F/M 与 S/M 的**符号**、心、铁栏、划掉的 `exit(0)`。
**这部片子的纸只承载"记号"。** 一个被十字四等分的方框不是记号——它不指向片子里的任何概念，
没有哪句歌词、哪行代码、哪个意象对应它。它是**抽象几何混进了一部符号学作品**。

### 改成：机器把程序倒着擦掉

`state` 那一行从 193 秒起就写着 `REWINDING`。**那这 13 秒就该真的在倒带。**
于是让程序**从最后一行开始逐行消失**（后写出来的先被擦掉），
18/19 行 `exit(0);` 和 `return you;` 保持划掉的状态消失——因为它们本来就没被执行过。

同时加进全片最后那个论点：纸的右下角**留一颗手画的心**，
程序一行行退场，**只有它越到后面越清楚**。
机器能收回自己写的代码，收不回她亲手画的东西——这也正好是下一镜 `final` 的全部内容，
所以结尾两镜第一次真正接上了。

实现上给 `code()` 加了第 5 个可选参数 `offFrom`（该索引之后的行不再绘制）。
前三个调用方不传它，行为完全不变。

### 结果

- `analysis/frame-powerdown-unwritten.jpg`（200 秒）：纸上只剩 10–14 行
  （`// runtime`、`world.execute(me);`、`me.run();`、`while (you.isPresent()) { me.stay(); }`、
  `you = null;  // though you have left`），15–19 行已经被擦掉，右下角心还在。
- `analysis/frame-powerdown-rewind.jpg`（193.2 秒起每 1.33 秒一格，共 9 格）：
  **10 行 → 2 行**的连续退场，加上纸本身在缩小，13 秒里第一次有了"正在发生一件事"的弧线。

### 重扫

1080P / 360 fps 全片重扫（76,287 帧，2117 秒）：尖峰 63 个
（27 `beat-cut` + 23 溶解 + 13 硬切），**未归因闪现 0 个**——上一轮那个峰值 8 的边沿告警

## 第十九次：摄影机一直没看向陷阱

上一轮结尾留了一组对不上的数：`chorus1` 的相机 x 在 60/64/69.1/71 秒分别是
497 / 879 / 661 / 585——**一条往右的摇镜，读数却来回跳**。当时没解释就停了。

### 先解释那组数：不是 bug，是两套运动叠在一起

按 `P = 16·60/128 = 7.5 s`、乐句横移 `arc·DW·0.1·dir = ±160`、慢漂移 `±88` 复算：

| t | 摇镜目标 | 相位 dir·arc | 漂移 | 算出的合位 | 实测 |
|---|---|---|---|---|---|
| 60.0 | 490 | ph8 · 0 | 0 | 490 | 497 |
| 64.0 | 633 | ph8 · +159 | +88 | 880 | 879 |
| 69.1 | 815 | ph9 · −159 | +5 | 661 | 661 |
| 71.0 | 832 | ph9 · −159 | −85 | 588 | 585 |

四个点全部对上（±7 px 是 slew 滞后）。**解释清楚了，同时也判了这场戏的死刑**：
摇镜全程只走 352，而乐句横移的峰峰是 320——**叠加运动的幅度几乎等于要表达的运动本身**。

更要命的是相位：`chorus1` 的落笼窗口 70.08–74 落在 ph9，`free` 的 188.48–192.6 落在 ph25，
**两个都是奇数相位，`dir` 恒为 −1**。也就是说在笼子落下这段时间里，乐句位移**只会往左拽**，
一次都不帮忙。

### 看像素定罪

### 双人镜头其实装不下，算过才知道差多少

`page()` 把纸又缩了 0.76，所以真正画出来的纸在设计空间 **227..713**；笼子在 **1088..1520**。
`z=0.95` 时半视宽 705，于是"两个主体都不被裁"的机位窗口只有 `x 767..932`——**165 px**，
而乐句行程是 **248 px**。原来的笼子宽度让这道题根本无解，所以三处一起改：

1. 笼子收窄到 `DW·0.24`（1088..1472），并改成**整体平移落下、落定后停住**，不再塌回地面；
2. `trapFrame` 落点从 `DW·0.52` 右移到 `DW·0.55`，`z` 从 1.06→1.00 放宽到 1.02→0.95；
3. 给单个镜头一个行程系数：`frame()` 可以返回 `arc`，`cameraFor` 用它同时缩放横移、
   漂移、俯仰抬升、滚转和变焦脉冲。这是**第一次让"这一幕要走多少"成为镜头自己的授权**，
   而不是全局运镜的默认值——`boundToSheet` 的注释早就写明"主体该在哪是逐镜的创作决定"，
   这次把"该走多少"也交还给它。`SETTLE` 交接与两种剪辑重建都会把 `arc` 带着走，
   否则交接的那 0.8 秒会突然拿到满行程。

### 重扫（第一次真正按 1080P 扫描）

先记一件工具上的事：`VERIFY.start()` 建好状态后自己驱动自己，**在这个宿主里跑不完**。
实测把 pump 挂在 MessageChannel + `setTimeout` 上，一轮 76,287 帧、纯算只要几分钟的扫描，
95 分钟还停在第 240 帧；改成"每 240 帧向本地 sink 发一个 `fetch().then()` 续跑"，
那个 POST 根本没到达服务器。**只有 CDP 调用之内的那段同步代码是可信的。**
所以扫描改成 `drive(ms)`：调用方给时间预算、页面在预算内同步跑完就返回，反复调用直到 `done`。
切片之间页面被冻住也无所谓——计数器和数组都在页面里，没有挂在待触发的回调上。

本轮：76,287 帧 @ 360 fps，backing store **2400×1350**，实际计算 2172 秒。

- 尖峰 64 个：27 `beat-cut`（峰值最大 87）+ 23 溶解（98）+ 13 硬切（35）
  + **1 个未归因闪现**：19.197 秒、`globe`、峰值 36、只占 1 帧。
- 这一轮是第一次按真实 1080P 采样，**数字与上一轮（backing store 更小）不可直接比较**；
  上一轮报的 0 未归因，是在更粗的采样下得到的。

那个闪现我先用两种办法证伪过自己的猜测：以为是顶条上移后拍尺每帧变化暴露出来——
量了小节号、拍尺、水印三个区域，最大逐帧变化只有 0–2，**不是它**；
又写了个临时探针想复现扫描的判据，结果它在 100 秒、120 秒这些安静窗口也报 85–96，
**说明坏的是探针不是片子**（判据本身要先验，这条已经吃过一次亏）。
所以目前它的状态是：已定位到 19.197 秒这一帧、峰值 36、单帧，机制未定。

### 我把一个判据读错了，并且已经把它写进了上一版 README

分幕统计里 `chorus`（59.22–74.04 秒）是：平均运动 0.0、运动峰值 **9**、运镜峰值 **7**，
而别的幕是 65–98 与 399–510。我据此写下"第一副歌成了全片最静的一截"，
并把它当成一个待修的缺陷。

**这个读法是错的，一行代码就能证伪**：数一下每一幕里"会移动相机的剪辑"（mode 1 特写 / mode 2 拉远）有几个——

| 幕 | 会移动相机的剪辑数 | 运镜峰值 |
|---|---|---|
| boot | 1 | 170 |
| interlude | 4 | 510 |
| verse(29.7) | 5 | 510 |
| **chorus(59.22)** | **0** | **6** |
| verse(74.04) | 1 | 510 |
| chorus(88.58) | 4 | 510 |
| execution | 5 | 510 |
| outro | 4 | 510 |

`panMax` 量的是**相邻帧之间相机跳了多远**，不是这一幕走了多远。
一次缓慢持续的摇镜每帧只动 0.1 设计像素，永远不可能把 `panMax` 顶高；
只有"切到特写"这种瞬移才会让它撞到 510 的钳位。第一副歌恰好是全片**唯一没有重新取景**的幕
（它 72.31 秒那个 cut 是 mode 3，不动相机），所以它的 `panMax` 低——
**这是在说它没有跳变，不是在说它没有动。**

教训本身比结论重要：**聚合指标的名字不等于它的语义**，`motionMax` / `panMax` 这种"峰值"量
天生偏向捕捉不连续，用它下"静止/活跃"的判断之前，先去看它到底在对什么求最大。
这一条和之前"判据本身要先验"是同一件事，我又犯了一次，只是这次在改画面之前先被数字拦住了。

### 这一幕最后还是改了，但理由换成镜头自己的调度

上面那个改动（开场 `z 1.15` 收紧在纸上、随摇镜退到 `0.95`，行程系数在落笼前 3 秒才爬降到 0.40）
我保留了，理由与那个错判据无关，而是画面自己的事：
**笼子要落进的那半边房间，得由摄影机自己让出来**——开场贴着纸，退开的同时向右摇，
落点正好是双人镜头，于是"陷阱出现了"这件事是随运镜被揭示的，
而不是像原来那样对着一个已经框好的空场等 11 秒。

- `analysis/frame-chorus-hold-before.jpg`（70.6 秒，改前）：纸在中间、只露出两根栏贴在右边缘。
- `analysis/frame-chorus-hold-after.jpg`（同一时刻，改后）：纸退到左侧，六根栏完整地从上方垂入。
- `analysis/frame-chorus-travelling.jpg`（62.7 秒）：行程中途，纸压到画面左缘、光标涟漪成为主体。

## 第二十次：联系表后半段——159 到 161 秒掉进来三块硬边红矩形

按 1080P 重扫后新的联系表（106–211 秒）逐格看下来，最扎眼的是 159 / 160 / 161 三格：
**纯红矩形 + 白字**，带笔直的四条边，和片子其余部分完全不是同一种东西。放大到
`analysis/frame-chant-slab-before.jpg`（160 秒）确认是两个独立的毛病。

### 毛病一：那块红是"填充矩形高斯模糊"，不是光

```js
g.save(); g.filter = 'blur(34px)'; g.fillStyle = rgba(ACC, 0.5);
g.fillRect(L.x, L.y, L.w, L.h); g.restore();
```

34 px 的模糊只能把边沿软化 ±50 px 左右，而这块矩形是设计空间里 800×380，
相机在 `z 1.5` 下把它吹大之后，**左边缘和上边缘仍然是两条可以用尺子画的直线**，
右和下又被画框切掉——于是它既不像光也不像色场，像渲染残留。
全片其他任何一处色场都是渐变，没有可见边界。

改成以字为中心的径向渐变（0.5 → 0.3 → 0），去掉 `filter`：
`analysis/frame-chant-wash-after.jpg` 里红变成了房间自己在发红，
地板线、波形、暗角都透得出来，六个数字脚下那排"划掉的节点"也重新落回地面上。

### 毛病二：相机被短语位移拽离了这一幕自己的主体

量出来很干脆：`count` 写的是 `x: DW * 0.5 = 800`，而 160.0 秒相机实际在 **x 585**——
**偏开自己的主体 215 设计像素**。这一幕没有纸，所以 `boundToSheet` 完全管不到它。
肉眼确认到的后果：改前 159.05 秒的 EIN 和 160.0 秒的 TROIS 都不居中，
TROIS 的最后一个字母已经压在画框右缘上。

215 这个数不是玄学：那一时刻 `ph = 21`（奇数 → `dir = -1`），
`arc·160 + drift·88 = 138.6 + 76 = 215`，分毫不差。

**修法选择的不是"给这一幕写个 arc: 0"，而是一条规则**：
`CUTS` 的生成器里早就写着 `/* the chant edits itself; leave it alone */`——
带 `cut: true` 的幕不吃自动剪辑。同一句话应该也对相机成立：
**一幕如果自己在按拍切自己的取景，就不该同时被乐句位移搬走**，那是噪声不是运动。
所以规则落在 `cameraAt` 的一处默认值解析里，自动覆盖 `chant` / `sentence` / `count` 三幕，
而不是在三个 `frame` 里各写一遍 `arc: 0`。

|---|---|---|

规则对显式写了 `arc` 的幕（两个 trap 镜头）不覆盖——默认值的解析顺序是
"幕自己写了就用幕的，没写才看 `cut`"，所以双人镜头那套算术一点没动。

### 已知没管的一处

交接的 0.8 秒里这个份额是从上一幕**插值**下来的，所以唱词第一次进入（147.66 秒）
的头不到一秒仍会带着上一幕的摆动。这是 `SETTLE` 存在的理由（不插值就会跳），
先记账不动它。

### 但眼睛顺着顶行找到了真的第三个硬边方块

看 211 秒的印刷尺寸帧时发现的：遥测面板自带一块 `fillRect` 遮罩，
**只有左边缘做了渐变，上、下、右是直线**。
在一个几乎什么都没剩下的暗房间里，它就是一块浮在黑场上的浅灰卡片——
和刚修掉的唱词红矩形是同一个毛病，而且就在全片最后一个画面上。

- `analysis/frame-panel-soft-after.jpg`（211 秒，改后）：读数直接落在黑暗里，没有任何边界。
- `analysis/frame-panel-legible-check.png`（160 秒，3× 裁切）：
  **遮罩该起作用的时候还在起作用**——压在红色光场上时读数依然可读、分隔线清晰，
  只是不再有一条边。

顺带确认了另一条既有规则没被破坏：120 秒页面正被推近（`EDIT === 1`），
面板按"读数是全景元素，推近后就是杂物"整块隐去——这是设计，不是 bug。

## 三次返工：从可视化到一间暗房

**第一轮**是亮色纸面配灰线，被指"颜色呢"——量出来确实是问题（亮段饱和度实测 0.01–0.04）。
**第二轮**改成饱和地面色 + 两档山脊 + 大太阳 + 平涂道具，颜色够了，但被指"太乱"，
再被直接判为"非常丑"。回头看，病根不在配色而在**语言**：canvas 擅长画光、衰减、剪影，
不擅长画卡通小物件；我让它去画茄子、狸猫、棋子、房子，它就一律给你 clip-art。

**第三轮（现在这版）换了语言**：房间全黑，**那张纸是唯一光源**。歌词说到什么，就用墨线画在
发光的纸上；情绪不再靠换色相，而靠灯——副歌过曝、崩塌段灯丝烧黄、诵唱段房间变成判决的颜色、
结尾是灯离开房间。先做了三张真渲染的风格样片（`style-a/b/c.jpg`）选定方向，才动手重写。

这条语言顺带解决了两件事：所有图元都被**裁在纸内**，物理上不可能再压到字幕或彼此叠穿；
以及"一帧里有多少东西"从十几个常驻图层降到"一间屋子、一张纸、一个节点"。

转场的病根与配色无关，而在**每个镜头各自持有摄影机**：溶解时新旧两幅画用不同缩放，
于是变成"带淡入的跳切"。现在全片只有一条摄影机轨道，切点处保持上一镜落幅、用 0.8 秒滑入
下一镜起幅；溶解时长随响度从 1.15 秒收紧到 0.45 秒。镜头内部换取景原本是**单帧瞬移**
（16 处，逐帧扫出来的），现在除诵唱段外一律 slew 过去；诵唱段的硬切是它的剪辑语法，保留。

刻意**没有**做的：跟随鼓点的闪光、切片故障、以及摄影机无目的的漂移。之前有一条按响度缩放的
二阶正弦漂移常驻每一帧（幅度 8–26 像素），读起来像"画面静不下来"，整个删了。唯一保留的震动
在高潮段，由镜头自己声明 `shake` 才生效，幅度挂在实测 onset 的冲量上——鼓点停，画面就停。

设计空间原来用 `cover` 铺满窗口：窗口一旦不是 16:9，画面两侧就被裁掉，代码清单会少掉左边几列。
现在改成 `contain` 加黑边，1600×900 这一页在任何窗口比例下都完整可见。

一个需要你知道的取舍，以及它的修正：第三版曾**刻意接近单色**（房间黑、纸白，全片只有那一抹绯红），
当时我认为要更花就得走回第二轮那条会被判丑的路。看了 Luminite 之后发现这条路是存在的：
**每个段落只用有限的几块颜色，但段落之间换整套**。现在全片是六套三色板——
开场中性纸白、主歌普鲁士蓝的夜、副歌黑/朱红/金、崩塌段褐黄、`EXECUTION` 判决红、揭示段淡紫冷光，
结尾是灯离开房间。房间始终是全黑的，颜色活在那盏灯的温度里。

## 背景与配器（查证到的，不是猜的）

```
        0s  15s  30s  45s  60s  75s  90s 105s 120s 135s 150s 165s 180s 195s 210s
平坦度   23   53   22   24   54   18   25   43   41   18   21   55   51   73  240
```

主歌段平坦度 18–25、有音高比例 60–94%（旋律与合声在说话）；一到副歌入口、诵唱段、
结尾的芯片琶音，平坦度跳到 43–73、有音高比例掉到 28–37%（噪声性、打击性的材料浮上来）；
最后 10 秒是纯噪声尾音（平坦度 240，几乎没有音高）。
**亮度反而不是区分两者的量**（高频能量占比全程稳定在 19–25%），区分它们的是"有调 / 无调"。
胶片颗粒的强弱因此挂在实测平坦度上，而不是挂在响度上——听到的是噪声层浮上来，
看到的才是画面变粗。

需要说清楚的是：DSP 只能把材料分成"有调 / 噪声性"，**不能凭频谱报出乐器名字**。
上面关于编制的说法来自乐队自己的公开资料，不是我从音频里"听"出来的。

## 校验：逐帧扫，不是抽查

按"每秒校验 60 次画面、后来调到 120 次"的要求，`analysis/verify.js` 把全片 211.907 秒按
120 fps 展开成 **25,429 帧**（`VERIFY.start(120)`），每一帧都真的渲染出来再量：

- `MV.pin(t) / MV.step(ts)` —— 播放器暴露的可 pin 时钟。靠 `track.currentTime` 是做不到
  逐帧的：媒体 seek 要一个异步往返才能改变播放位置，而 seek 的粒度也远大于 16.7 ms。
- 每帧量四个数：亮度均值、饱和度均值、**与前一帧的差**（运动量）、以及摄影机本帧的位移速率。
  运动量是症状层的量——"画面在乱抖"这件事只能在这里被证伪；摄影机速率是原因层的量。
- 每 60 帧取一格，同时拼出每秒一格的接触表（`sheet-a.jpg` / `sheet-b.jpg`）。
- 阈值：亮度 <8 记为黑帧，>247 记为爆白，帧间运动 >70 或摄影机速率 >26 记为跳帧。

一个注意点：分析数据本身是 21.33 ms 一帧（46.9 fps），所以 60 fps 下部分帧只是插值差异。
仍然要按 120 fps 扫——因为画面是按帧显示的，一帧的闪屏在 47 fps 采样下会被整个漏掉。
事实正是如此：**这条链路上抓到的三个 bug，有两个只存在于个别帧上，第三个只在时钟被倒着拨时出现**。

| 抓到的 | 症状 | 根因 |
| --- | --- | --- |
| 片尾 3 帧全黑并抛异常 | `addColorStop('#NaNNaNNaN')`，t ≥ 211.886 | `NF` 取了 base64 **字符串**的长度 13,244，而解码后只有 9,933 帧；末尾越界读到 `undefined` → NaN 一路传到渐变色 |
| 16 处单帧跳变 | 运动量曲线上 4.8 / 47.7 / 49.5 / 51.4 / 55.1 / 77.6 / 81.4 / 85.1 / 92.0 / 95.5 / 99.3 / 103.5 / 117.3 / 124.9 / 179.9 / 180.9 秒各一根针 | 镜头内部换取景是瞬移（第 N 帧宽、N+1 帧紧，中间没有过渡）；现在除诵唱段以外一律 slew 过去 |
| 时钟倒退一次，整片从此不刷新 | 逐帧扫时 23,616 / 25,429 帧被标记，异常是 `rgba(0,0,0,Infinity)` | `render()` 拿 `(ts-lastTs)/1000` 当 dt，倒带时 dt 为负，`1-exp(-dt/τ)` 溢出成 `-Infinity`，把调色板污染成 `±Infinity` 且**永久粘住**（渐晕那一行最先抛）。真实用户点一下波形上更早的位置就会踩到 | dt 先 `Math.max(0, …)` 再进任何平滑器 |

代码层面完全看不出来。

证据图一律走 `shot()`：它把舞台的 CSS 盒子按 1920×1080 摆好、派发 `resize`、pin 住时钟再渲染，
然后把 canvas 自己 POST 给本地服务存盘。之所以不让截图工具来拍，是因为 hidden 页面的
`take_screenshot` 会返回**上一帧**的陈旧合成帧——我一度因此复核错了图。
`report()` 之后 `verify-<rate>fps.png` 的文件名跟着扫描速率走，图上的曲线数量与判据同源。

`analysis/verify-120fps.png` 是五条曲线（亮度 / 饱和度 / 帧间运动 / 摄影机速率 / 细节密度），
竖线是幕边界。运动曲线现在是一条贴地的直线加几根孤立的针，针集中在 147–163 秒——
那是诵唱段**要求**的硬切（`scene.cut`），不是残留的抖动。

### 120 fps 才看得见的那类 bug：闪现

你说"调到 120 张每秒，然后你就会发现部分元素在闪现"。确实如此，而且 60 fps 扫不出来：
一次闪现只有一帧，在 120 fps 下它是一根 8.3 ms 的针。

判据不能只是"这一帧和上一帧差得多"——硬切也差得多。所以每个孤立尖峰要**先归因再计数**：

| 归因 | 规则 | 算不算 bug |
| --- | --- | --- |
| `dissolve` | 落在某个切点 ±1.5 秒内（溶解最长 1.15 秒） | 否，转场本来就要换画面 |
| `hard-cut` | 落在声明了 `cut: true` 的镜头里（诵唱段的剪辑语法） | 否，那是设计 |
| `FLASH` | 其余：元素在镜头内部凭空出现、消失或被重新驱动 | **是** |

归因之后计数为 0（下表是修完之后的最终一轮）。修掉的三处真闪现：

| 时间 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 69.15 s | `> run execution` 每 0.09 秒"跳"出一个字符 | 打字机写成 `slice(0, floor(u*20))`，一个字形在一帧内从无到有 | 改成一条连续变宽的裁剪带，字是被擦出来的 |
| 134.8 s | 堆栈跟踪那一页整页消失 | `if (t < 134.8)` 是硬门，一帧之内整张纸没了 | 让纸连同裁剪一起在 134.8–135.55 秒淡出 |
| 各切点 | 溶解窗口随响度实时改变 | 混合期间音乐变响 → 窗口缩短 → 条件中途转假 →  incoming 画面被弹回去 | 溶解时长改为在**切点那一刻**取样（`dissolveLen(nxt.from)`），窗口一开就固定 |

还有一处不算闪现、但同样只有逐帧才看得见：`void` 里的光标用 `Math.floor(t*2)%2` 开关，
每 0.5 秒硬开硬关一次；改成余弦呼吸之后它不再产生边界帧。

顺带说一个只在真渲染下才会暴露的排版 bug：逐字打字需要按字宽排 x，而 `measureText` 用的是
**当时**的字体——上一次 `G.text` 把字号改成了行号的小字号，于是整行字符叠在一起。
1920×1080 的定点图一眼就看出来了（`> run exe.cuti..`）。这也是这一轮改成裁剪带的原因之一。
